医药 ERP 业务流程全览

GMP 生产 + GSP 经营 · 11 大业务流程 · 采购 · 采购退出 · 生产 · 采购付款 · 物料检验不合格处理 · 质量复验 · 销售 · 销售退回 · 销售收款 · WMS 仓储 · 商品养护

说明：GMP（药品生产质量管理规范，生产型企业）与 GSP（药品经营质量管理规范，经营/流通型企业）的采购流程、采购退出流程、销售流程、销售退回流程完全不同，故 01、02、07、08 四张卡各自拆成 GMP 版与 GSP 版两个章节；03～06、09～11 为通用流程骨架，卡内会按需点出 GMP / GSP 的差异。
01采购流程GMP 版
业务流程 01 · 采购流程（来料：原料/辅料/包材） 模块：采购 → 质检 → 仓储 · 初验单（收货前置）+ 放行双拦截 · 先入后退
主线流程
流程速览：先讲主干（初验 → 收货 → 请验 → 取样检验 → 放行 → 入库），再往阶段里塞细节。注意 初验在收货之前，采购收货单要提取物料初验单；检验不合格还有"返工复检"岔路（见业务流程 05）。
1
一句话目的
把采购到货的原辅料/包材，按 GMP 要求完成取样检验，由质量负责人判定放行后入库，保证只有合格物料能进生产、全程可追溯。
2
触发条件
采购订单审核通过、物料到货后，由现场 QA 做物料初验启动这条流程；初验合格才进收货环节。
3
前置 / 上游
采购申请单 → 采购订单已生效；物料档案（含质量标准）已建立；供应商已审核。
4
主线步骤
① 申请 → 订单（要什么、跟谁买）
② 到货 → 物料初验单（现场 QA 目视判断——初验在系统里以状态记录、不设检验项目：初验状态 + 来料状况；批号在这一步生成）→ 拒收的直接退，不进后续流程
③ 收货 → 采购收货单（提取物料初验单；核对数量品种；批号来自初验单，有供应商批号的物料改成原厂批号）
④ 请验 → 取样 → 留样 → 项目确认 → 任务分发 → 结果登记 → QA 主管审批 → 检验报告单
⑤ 质量负责人审批 → 放行单　⑥ 无论放行与否都先入库：放行 → 正常库存可用；不放行 → 入库后走采购退出退货
⑦ 检验不合格的岔路：不是所有不合格都要退——先走「物料检验不合格处理」（晒干 / 过筛 / 退货），返工后只复检不合格项目，合格仍可放行 → 详见业务流程 05
⑧ 退货的物料入库后：要在不合格登记单里登记（不合格品台账，留痕）
5
关键单据与字段
物料初验单：批号（在这一步生成）｜初验在系统里以状态记录、不设检验项目，全靠现场 QA 目视判断，只有两个状态字段：初验状态（合格 / 拒收 / 待处理）+ 来料状况（需处理 / 无需处理 / 处理中）｜采购收货单提取物料初验单
收货单：实收数量（与订单差异）、批号（来自初验单；有供应商批号的改成原厂批号）
不合格登记单：只记录已入库物料的不合格（品名 / 批号 / 数量 / 不合格原因 / 处理方式）——初验拒收的货没入库，不登记
取样单：厂内批号、取样件数｜留样单：留样数量 ≥ 全检量、保存期｜报告单：各检验项目结论｜放行单：质量负责人签字、放行结论
6
异常与回退
三道关口，两条退货路径：
① 初验关（收货前，现场 QA 目视）：不合格 → 初验状态=拒收，不入库；合格 → 来料状况=无需处理，走正常流程
② 检验关（内在质量）：不合格 → 先走「物料检验不合格处理」——水分不行选晒干、杂物多选过筛，返工后只复检不合格项目，合格照样放行；物理方法救不了才选退货
③ 放行关（QP 终判）：复检仍不合格 / 选了退货 → 不放行 → 先入库（物理隔离）→ 在不合格登记单登记 → 走采购退出退货，库存冲减
数量差异 → 按实收处理；单据填错 → 未审核反审核，已审核红冲
7
下游衔接
初验拒收的货直接退供应商，不产生库存；返工复检合格的物料正常入库可用；放行入库后接生产领料/投料（按批号追溯）；检验不放行的接采购退出流程（退货，见业务流程 02）；财务做应付账款与发票核对（见业务流程 04）。
客户信管检查点（上线后要盯的 六 点）

① 为什么不合格也要审批过去？ → 权限分层：QA 主管只核"检验完成度"，质量负责人掌握放行否决权，流程不能卡中间，要让 QP 看全信息做终判。

② 留样留多少？ → 至少够全检重做一遍的量（全检量）。

③ 不放行的货怎么办？ → 物理上隔离（不合格品区，绝不用于生产）；账上先入库再走采购退出退货，库存冲减——账实两清。

④ 初验拒收和检验不放行都是退货，区别在哪？ → 时机和单据不同：初验是外观关（收货之前拦截，现场 QA），货不入库、直接退；检验不放行是内在质量关（QP 终判），货已入库，必须走采退冲减库存。容易混淆。

⑤ 检验不合格一定要退货吗？ → 不一定！先走「物料检验不合格处理」：水分不行选晒干、杂物多选过筛，返工后只复检不合格项目，合格仍可放行——这是中药饮片特有的"物理返工"，物理方法救不了的才退货。

⑥ 初验在系统里怎么记录？ → 初验在系统里以状态记录、不设检验项目，全靠现场 QA 目视；只有状态字段：初验状态（合格 / 拒收 / 待处理）+ 来料状况（需处理 / 无需处理 / 处理中）。合格对应"无需处理"、正常走流程。

留样单 · 详解

留样不是"确认产品有没有问题"——检验已经干了这活儿。留样是给这批货留一份"事后复查"的证据。
5
三个要点
数量：留样量 ≥ 全检量（把检验项目完整重做一遍的量）
保存期：通常到该批物料效期后 / 按 GMP 规定期限
用途：质量争议、客户投诉调查、稳定性考察、年度质量回顾
一句话记：留样 = 事后追溯的底稿
01采购流程GSP 版
业务流程 01 · 采购流程（来货：药品 / 中药材 / 非药品） 模块：采购 → 验收 → 仓储 · 收货 → 验收 → 上架 → 入库 · 验收前置拦截 + 待处理分流
主线流程
流程速览：先讲主干（采购订单 → 采购收货单 → 采购验收单 → 上架 → 采购入库单），再往阶段里塞细节。GSP 经营端不做物料初验、不做 QA/QC 检验——收货后直接验收，合格上架入库、不合格走验收退货；有 WMS 时验收多数落在手持 WMS里做。特殊是"待处理"：质量专员提待处理单，由质量主管/经理判定后再分流。
1
一句话目的
把采购到货的成品（药品与非药品），按 GSP 要求完成收货验收，验收合格即上架入库，不合格走验收退货，保证只有合格品能进库销售、全程可追溯。经营范围涵盖：化学药（含化学原料药/生化药品/抗生素）、中成药、中药饮片、中药材、生物制品、体外诊断试剂等药品；另可兼营化妆品、保健食品、农产品等非药品品类（非药品不属 GSP 药品经营范围，需另办许可，同系统管理）。
2
触发条件
采购订单审核通过、货物到货后，由仓管人员做采购收货启动这条流程；收货完成进入验收环节，验收通过才上架入库。
3
前置 / 上游
采购申请单 → 采购订单已生效；首营企业 / 首营品种已审核批准（供货单位资质、药品合法性、销售人员资格、质量保证协议）；商品档案（含经营范围、储运要求）已建立。
4
主线步骤
① 申请 → 订单（要什么、跟谁买；首营要过质量审批）
② 到货 → 采购收货单（仓管核对到货数量、品种、包装；可多次收货、实收可小于订单量；发现破损/发潮发霉/批号不符可直接拒收，拒收量必须小于收货量）
③ 采购验收单（收货后验收；合格 → 上架入库，不合格 → 走验收退货）
④ 上架（有 WMS 时，上架任务自动分摊到合适货位，如中成药进 01-01-01；也可手动下发任务）
⑤ 采购入库单（上架完成后在 ERP 做入库，ERP 库存增加；WMS 已加货品数量、无需再做入库）
⑥ 特殊分流——待处理：验收时拿不准 → 质量专员在系统提取采购验收待处理单 → 质量主管/经理检验判定 → 合格走入库、不合格走验收退货
⑦ 退货/拒收：收货环节可拒收（数量不够、破损、发潮发霉、批号不符）；验收环节不合格走验收退货（系统内置该功能）
5
关键单据与字段
采购收货单：实收数量（与订单差异、可多次收货）、拒收数量（须小于收货量）、批号（见下方"批号问题"）
采购验收单：验收结论（合格 / 不合格 / 待处理）、验收数量、批号、效期、储运条件｜验收可在 ERP 或手持 WMS / WMS 软件中做
采购验收待处理单：质量专员提取，附待处理原因，经质量主管/经理判定后分流
验收退货单：不合格/待处理不合格的退货去向、数量、原因（系统内置）
采购入库单：上架完成后 ERP 侧入库，库存增加｜WMS 已同步货品数量，不再重复入库
6
异常与回退
两道拦截，两类退货：
① 收货关——拒收：数量不够（很少见）、货品破损、发潮发霉、批号不符 → 直接拒收，拒收量必须小于收货量；收货数量可以小于采购数量，这是允许的
② 验收关——三选一：合格 → 直接入库；不合格 → 直接走验收退货（系统内置）；待处理 → 质量专员提待处理单，质量主管/经理判定后再分流
批号问题：除中药材外，西药、中成药等药品批号由生产企业在厂内已生成，收货时直接录入原厂批号即可；中药材同 GMP 企业，由经营端自建批号管理
7
下游衔接
验收合格的货上架入库、成为可售库存，接销售出库 / 养护 / 效期管理；验收不合格与待处理不合格的货走验收退货，直接退回供货商、不进库存；收货环节拒收的货同样不进库存。入库后财务做应付账款与发票核对（见业务流程 04）。
客户信管检查点（上线后要盯的 六 点）

① GSP 经营端为什么不做初验、不做检验？ → 因为药品批号由生产企业在厂内生成，经营企业是验收不是生产——只做数量/外观/批号效期核对，不做内在检验。别把 GMP 那套取样检验硬套进来。

② 批号怎么录？ → 除中药材外，西药、中成药等直接录入原厂批号（生产企业已生成）；中药材同 GMP 企业，经营端自建批号。

③ 验收"待处理"是什么？ → 拿不准合格/不合格时的中间态：质量专员提取采购验收待处理单，经质量主管/经理判定后，合格入库、不合格退货。别让它卡在半路。

④ 拒收和验收退货区别在哪？ → 拒收在收货环节（数量不够、破损、发潮发霉、批号不符），货还没收进来；验收退货在验收环节（不合格/待处理不合格），系统内置该功能。拒收量必须小于收货量。

⑤ 有 WMS 时验收在哪做？ → 验收多数落在手持 WMS（也可在 WMS 软件）；上架任务自动分摊到合适货位（如中成药 01-01-01），也能手动下发。上架完成 WMS 货品数量已增加，ERP 只需做采购入库、不再重复入库。

⑥ GSP 强制仓库要有啥？ → 电子标签拣货系统、传送带、复核台；电子标签拣货系统可与 WMS 接口对接（WMS 内含货位标签打印功能）。这是 GSP 硬性要求，别漏配。

WMS 与上架 · 详解

有 WMS 时验收与上架怎么做
GSP 强制要求医药企业仓库配备电子标签拣货系统、传送带、复核台；其中电子标签拣货系统可与 WMS 接口对接——WMS 系统内自带货位标签打印功能。（拣货时用电子标签拣货系统，本流程不展开。）
5
两条验收+上架路线
路线一 · ERP 里验收：采购订单下完、供货商发货、仓管收货后，在 ERP 做验收流程；做完验收，上架任务自动分摊到合适货位（如中成药进 01-01-01），跳进手持 WMS，仓管按货位扫码上架
路线二 · 手持 WMS 里验收：在手持 WMS 完成验收后，上架任务同样自动分摊到手持 WMS，但不区分人员；可在 WMS 开发"一个仓库货区对应一个库管人员"的功能
上架完成后：WMS 仓库对应货品数量增加（不需要做入库），仓库人员在 ERP 做采购入库，ERP 库存增加
任务下发与手持上架要点
上架任务可手动下发；实际业务中系统功能往往不能 100% 覆盖所有操作场景，我的处理思路是用线下 SOP 和留痕来兜底——比如上架任务下发后如需调整，先在系统外记录变更原因和操作人，再配合系统内的任务状态管理，确保每一步都有迹可循。
手持 WMS 上架很简单：上架任务下发后，仓管把货移动到对应货位，用手持扫描货位标签，确认上架数量、上架货位、库区等信息即可。
02采购退出流程GMP 版
业务流程 02 · 采购退出流程（退货） 模块：采购 / 仓储 · 采购流程的反向分支
主线流程
流程速览：采退 = 采购的"反向操作"。先讲两种触发原因，再讲"提取原单 + 数量约束"两个关键点，最后落"出库 → 库存减少"。
1
一句话目的
把"不该留在厂里的货"退回供应商——要么检验不合格，要么买多了消化不了；退的同时库存冲减、账实一致。
2
触发条件（两种情况）
① 质量原因：来货检验不合格（不放行），已走常规入库后触发退货；
② 数量原因：买多了，销售/生产消化不了，与供应商商定后退货。
3
前置 / 上游
必须已有采购入库单——采退开票单直接提取原单（入库单），并带出采购开票单单号。
质量原因退货的：物料已入库 → 先在不合格登记单登记 → 再走采退（接业务流程 05）。
4
主线步骤
采购退出开票单（采购员/业务员发起，提取采购入库单）→ 采购退出复核（当前无 WMS，先不做）→
采购退出出库单（仓储按数量拣货、退货发货）→ 出库 → 库存减少
5
关键单据与字段
采退开票单：提取原单 = 采购入库单、采退数量 ≤ 入库数量（系统校验点）、关联采购开票单单号
采退出库单：拣货数量、批号
6
异常与回退
采退数量超出入库数量 → 系统应拦截（不能退没入过库的量）
单据填错 → 未审核反审核，已审核红冲
7
下游衔接
财务冲减应付/红字发票（调价财务部分暂不展开）；库存与供应商往来对账。
客户信管检查点（上线后要盯的 三 点）

① 为什么采退单必须提取原单（入库单）？ → 保证退的是"入过库的货"，数量、批号、供应商全锁定，防止退无来源的货。

② 采退数量能超入库数量吗？ → 不能，只能 ≤ 入库数量。

③ 为什么现在跳过复核环节？ → 系统还没接 WMS，复核流程先不做，靠人工 + 系统基础校验兜底。

批号逻辑 · 详解

收货时系统自动生成批号那段，是这个流程最容易讲出彩的点
一句话：散装料用系统生成的厂内批号，带批物料改成供应商原批号。两条追溯链都要能查到。
5
为什么这么设计
中药材原料（编织袋散装）：本身没有供应商批号 → 用收货时系统自动生成的厂内批号，它就是内部追溯主键
经过加工的辅料/包材：供应商给了批号 → 把系统自动生成的批号改成供应商原批号，保留外部追溯信息
价值：出质量问题时，厂内批号查内部流转，供应商批号往回追到对方那一批货，两条链都能对上
02采购退出流程GSP 版
业务流程 02 · 采购退出流程（退货） 模块：采购 / 仓储 · 采购流程的反向分支 · 含退货复核（标签拣货）
主线流程
流程速览：采退 = 采购的"反向操作"。GSP 的退货有三种触发（验收不合格、滞销、数量错当天退），比 GMP 多。先讲三种原因，再讲"提取原单 + 数量约束"两个关键点，中间多一步采购退货复核（标签拣货），最后落"出库 → 库存减少"。
1
一句话目的
把"不该留在库里的货"退回供货商——验收不合格、滞销（近效期前退上游）、或采购数量错了；退的同时库存冲减、账实一致。
2
触发条件（三种情况）
① 验收不合格退货：采购验收不合格/待处理不合格，直接走验收退货（见业务流程 01）；
② 滞销退货：产品滞销，在没有近效期之前退给上游供货商（GSP 特有场景）；
③ 采购数量错了：数量录错，可在同一天做采购退货流程纠正。
3
前置 / 上游
必须已有采购入库单——采退开票单直接提取原单（入库单），并带出采购开票单单号。
验收不合格退货的：在采购验收环节就走验收退货（见业务流程 01），货没进正常库存；滞销/数量错退货的：货已入库，从库存里退。
4
主线步骤
采购退出开票单（采购员/业务员发起，提取采购入库单）→
采购退货复核（GSP 特有、GMP 没有——退货拣货任务下发后，用电子标签拣货系统打印拣货标签拣货，见下方详解）→
采购退货出库单（仓储按数量拣货、退货发货）→ 出库 → 库存减少
5
关键单据与字段
采退开票单：提取原单 = 采购入库单、采退数量 ≤ 入库数量（系统校验点）、关联采购开票单单号
采退出库单：拣货数量、批号
退货拣货标签：含货位信息，WMS 绑定打印，供扫描枪扫描拣货
6
异常与回退
采退数量超出入库数量 → 系统应拦截（不能退没入过库的量）
数量录错 → 当天做采退纠正；单据填错 → 未审核反审核，已审核红冲
7
下游衔接
财务冲减应付/红字发票（调价财务部分暂不展开）；库存与供货商往来对账；退货出库后库存减少，账实一致。
客户信管检查点（上线后要盯的 四 点）

① 为什么采退单必须提取原单（入库单）？ → 保证退的是"入过库的货"，数量、批号、供货商全锁定，防止退无来源的货。

② 采退数量能超入库数量吗？ → 不能，只能 ≤ 入库数量。

③ GSP 的退货复核是什么？ → GMP 没有这一步，GSP 有：退货拣货任务下发后，用电子标签拣货系统打印拣货标签（含货位信息），扫描枪扫标签、货位蜂鸣器亮起、总控制器显示货位、标签亮灯显示拣货量，拣完拍灭标签。

④ 复核台要吗？ → GSP 有复核台（GMP 不确定），出库货位一般是复核合格的才出。

退货复核与标签拣货 · 详解

GSP 特有、GMP 没有的环节，电子标签拣货系统在这里派上用场
一句话：退货拣货任务下发 → WMS 绑定打印拣货标签（含货位信息）→ 扫描枪扫标签拣货 → 蜂鸣器 + 总控制器 + 亮灯标签三重提示 → 拣完拍灭标签。
5
拣货完整链路（尽量还原现场）
第一步 · 任务下发：退货拣货任务下发后，WMS 绑定打印拣货标签（标签里含货位信息）
第二步 · 扫描：用标签打印的扫描枪直接扫描拣货标签
第三步 · 三重提示：① 货位上的蜂鸣器亮起（一个库区一个，如中成药拣货任务 → 中成药库区蜂鸣器响+亮）；② 每排货位的总控制器显示出对应货位；③ 对应的标签亮起并显示拣货数量
第四步 · 拣完拍灭：拣完货后，直接拍灭对应的标签按钮（这套"亮灯→拍灭"的现场操作比较抽象，理解成"灯亮提示该货位有活、拍灭表示干完了"）
复核台
GSP 有复核台（GMP 不确定有没有），出库的货位一般是复核合格的才走退货出库。
03业务流程 03 · 生产流程
业务流程 03 · 生产流程（两段式：中间品炮制 → 成品包装） 模块：生产 · BOM 驱动 · 两段独立检验 · 批号贯穿
主线流程 · 两段式
流程速览：先讲"两段式"骨架（炮制→包装，中间品是衔接点），再讲每段内部"指令→审批→领料→排产→工序→完工→请验检验→入库"——检验放行后才入库（顺序：完工→请验→入库）。BOM 和免检勾选是前置，别漏。
1
一句话目的
企业是生产型，需生产出自己的产品售卖盈利。具体做法：把原药材经炮制加工成中间品，再包装成可售卖的成品饮片。全程按 BOM 工序走、按批号追溯，每段产出都经检验放行后才能进入下一段或销售。
2
触发条件
有生产/销售计划需要产出成品时，由车间主任/负责人发起生产指令。前提是 BOM 和流程定义已维护好、原药材已入库放行。
3
前置 / 上游
① BOM 清单已维护（中间品 BOM + 包装 BOM，含工序序列、免检勾选）
② 生产流程定义已建好（中间品流程 + 包装流程）
③ 产品流程定义中已绑定产品
④ 原药材已入库且检验放行（接采购流程下游）
⑤ 批号规则已配置（指令保存时自动生成）
4
主线步骤（两段结构相同，投料来源不同）
第一段 · 中间品炮制（投料 = 原药材）
① 生产指令（车间主任发起：填中间品品种 + 投料量 + 主料 + 勾 BOM + 入料库房 + 生产车间，自动生成批号）→ 质量主任审批（两段各审一次：中间品生产指令审一次，成品包装生产指令再审一次）
② 领料开票单（提取指令，确认领料数量）→ 领料执行
③ 排产管理（排生产时间、生产设备）
④ 批生产工序记录（洗药→润药→切制→风干，每道记起止时间、产出量、操作人工作量）
⑤ 完工确认 → 生产请验（最后一步工序不勾免检；顺序为：完工→请验→入库，检验在入库前）
⑥ 检验链：取样→留样→项目确认→任务下发→登记→审核→报告单→放行 → 成品入库（中间品入库）

第二段 · 成品包装（投料 = 第一段中间品）
同样八步：领料提取包装生产指令，工序 = 包装 → 完工 → 请验 → 检验放行 → 成品入库 → 可售
5
关键单据与字段
生产指令：品种、投料量、BOM 清单、入料库房、生产车间、批号（自动生成）
BOM 清单：工序序列、是否免检（决定检验时机）
领料开票单：领料数量（提取指令）｜批生产工序记录：工序起止时间、产出量、操作人、工作量
检验放行单：质量负责人放行结论
6
异常与回退
免检勾选决定检验时机（核心控制点，实际采用②）：
① 全部勾免检 → 入库后才请验（系统支持的另一种模式）
② 最后一步工序不勾免检 → 完工后先请验、检验放行再入库（实际采用：完工→请验→入库）
检验不放行 → 不能投入使用/销售，隔离处理
领料数量与指令不一致 → 按实际领料；工序产出量异常 → 记录实际产出，差异需说明
7
下游衔接
第一段中间品放行 → 作为第二段包装的投料；第二段成品放行 → 成品库存（可售）→ 接销售出库；批号贯穿两段，从原药材到成品全程追溯。
客户信管检查点（上线后要盯的 四 点）

① 为什么一个饮片要维护两个 BOM？ → 分两段生产：中间品炮制 BOM（工序：洗润切风干）+ 包装 BOM（工序：包装），两段各走独立的生产指令和检验链。

② 免检勾选有什么用？ → 决定检验在哪触发：全勾免检 = 入库后请验；最后一步不勾 = 完工后先请验、放行再入库（实际采用）。

③ 两段的检验流程一样吗？ → 一样，都是请验→取样→留样→项目确认→任务下发→登记→审核→报告单→放行。

④ 衔接点在哪？ → 第一段中间品放行后，作为第二段包装生产指令的投料。批号贯穿全程，从原药材到成品可追溯。

BOM 免检勾选 · 详解

本流程里最容易混淆的控制点
免检勾选不是"这步要不要检验"，而是检验在哪一步触发。勾了免检 = 这步产出直接放行不卡检验；不勾 = 这步产出要触发检验链。
5
两种模式
模式 A：入库后请验 → BOM 所有工序全勾免检 → 走完工序、完工、入库后，再发起请验（系统支持的另一种模式）
模式 B：工序后请验 → 最后一步工序不勾免检 → 完工后先请验，检验放行再入库（实际采用）
一句话记：全勾 = 入库后检；最后一步不勾 = 工序后检、放行再入库
04业务流程 04 · 财务流程-采购付款
业务流程 04 · 财务流程：采购付款（应付） 模块：财务 · 进项发票登记 → 付款计划 → 勾兑结算 · 双路径 + 冲错回退
主线流程
流程速览：先讲"三个管"——发票管该付多少，勾兑管这笔钱对哪张单，付款计划管什么时候付。再讲两条路（走计划 / 跳过计划），最后补冲错回退。采购付款 GMP 生产企业和 GSP 经营企业通用——都是企业跟供货商的往来结算，经营企业没有额外的特殊校验或单据。
1
一句话目的
把"该付给供应商的钱"算清楚、付出去、对上账：以进项发票确定应付金额，以勾兑结算确定钱和单据的对应关系，以付款计划管控付款节奏，最终应付结清、账实一致。
2
触发条件
采购入库完成后，供应商按入库情况开票，发票到手，财务出纳即可发起进项发票登记。（开票依据 = 采购入库单 / 采购退回出库单 / 采购冲差单，不是采购订单。）
3
前置 / 上游
① 采购入库单（及退回出库单、冲差单）已审核，处于"待开发票"状态；② 供应商档案、银行信息已维护；③ 上游接采购流程 / 采购退出流程。
4
主线步骤（两条路，可跳过计划）
第一步 · 进项发票登记（财务出纳）：选供应商 → 点"按单据选择"（或按明细选择）→ 弹窗筛选"待开发票" → 查询出采购入库单、退回出库单、冲差单 → 勾选单据 → [选择完毕] → 单据落"发票单据明细"、商品落"发票商品信息" → 选发票类型/发票分类、录发票号码/发票日期 → 确认金额（价税分离：含税价拆成金额+税额）→ 确认完成
第二步 · 采购付款计划（采购开票员，可选）：出纳通知开票员 → 选供应商 → 提取数据（带出发票金额=结算余额）→ 按单据录结算金额 ≤ 发票金额（超出系统拦截）
第三步 · 采购勾兑结算：选勾兑方式——做了计划选"按计划勾兑"，没做计划选"按单据勾兑 / 按单据明细勾兑" → 提取计划/数据 → 下一步进结算界面 → 全部结清 → 完成 → 返回选支付方式 → 保存，应付结清
5
关键单据与字段
进项发票登记：发票类型（增值税普通发票等）、发票分类、发票号码、发票日期；明细自动带出含税金额、金额、税额、税率
付款计划：结算金额 ≤ 发票金额（核心校验点）、结算余额
勾兑结算：结算方式、勾兑方式、支付方式、预付款、支票号；已开发票金额 / 未开票金额 / 已结算金额
6
异常与回退
发票金额开错且已勾兑结算 → ① 先到进项发票作废把错票作废 → ② 再到采购付款冲红把勾兑结算单冲掉 → 回到登记重新开票。顺序不能反——结算单引用了发票，先解引用才能冲
结算金额超发票金额 → 系统提示拦截，不能超
一张票结不清 → 可与供应商协商开多张发票分期结清（部分结算，余额下次继续勾兑）
7
下游衔接
应付账款核销 → 总账凭证（进项税额，专票可抵扣、普票一般不可）；与供应商往来对账；付款计划数据反哺资金计划。
客户信管检查点（上线后要盯的 四 点）

① 结算金额为什么不能超过发票金额？ → 发票是付款的依据和上限——票面金额 = 这批单据"该付多少"的法律凭证，超票付款等于无依据付款。

② 付款计划的作用？跳过行不行？ → 计划是管控层：规划"何时付、付多少"且需审批，采购部门全程参与；跳过也能付（按单据/明细直接勾兑），但变成财务单方操作，采购可能不知情——跨部门失控 + 付款节奏乱。

③ 冲错为什么先废票、再冲红？ → 勾兑结算单引用了发票数据，必须先把引用解开（废票），才能冲掉结算单（冲红）；反过来系统会卡住。

④ 为什么采购退出出库单在开票/勾兑里是负数？ → 退货冲减应付——多退的货少付钱，负数单据在勾兑时抵减应付金额。

关键结论

① 单据名称：采购付款计划——方向是应付。

② 开票时点：采购入库之后。

③ 三种勾兑方式：本质逻辑一样，只是显示内容不同——按单据勾兑只显示单号/金额/公司、按计划勾兑只显示计划单号/金额/公司、按单据明细勾兑显示单条单据的所有商品明细（见下方"三种勾兑方式"卡）。

三种勾兑方式 · 详解

勾兑 = 把"付出去的钱"和"收进来的单据"挂钩核销 · 三种方式的显示差异
一句话：勾兑 = 把"付出去的钱"和"收进来的单据"挂钩核销。三种方式的区别看两个维度：界面显示的内容 + 采购部门有没有参与。三种方式本质逻辑一样，无非显示的东西不同——下面把实测的显示差异写清楚。
1
维度一：三种方式显示的内容
按单据勾兑：只显示出库单 / 退货单 / 入库单 / 退回单的单号、金额、公司等信息——粒度 = 单据，看不到商品明细
按单据明细勾兑：显示入库单 / 出库单 / 退货单 / 退回单的所有商品明细（注意是单条单据的明细，不是所有单据）——粒度 = 明细行
按计划勾兑：只显示计划单号（系统自动生成）、金额、公司名称（供应商或客户）——粒度 = 计划
2
维度二：管控差异
行业口径：结算计划要经过相关部门审批，审批通过才允许执行。所以——
走计划：计划编制 + 审批，采购部门全程参与，付多少、何时付有依据
跳过计划（按单据 / 按明细）：财务出纳单方直接勾兑付款，采购部门可能不知情——票登记了、钱付了，采购那边没人对过
风险：① 跨部门失控（金额争议、退货冲抵没人把关）② 付款节奏脱离资金计划
3
一个要理顺的混淆：勾兑 ≠ 开票
开票永远是"进项发票登记"那一步（财务出纳登记供应商开来的发票）；
勾兑是"付款核销"环节（钱和单据挂钩）。
准确说法：跳过计划时，财务出纳直接按单据/明细进行勾兑结算付款，而不是"直接开票"——开票和勾兑是两步，别说混。
05业务流程 05 · 物料检验不合格处理与复检
业务流程 05 · 物料检验不合格处理与复检 模块：质检 → 仓储 → 采购 · 返工复检闭环 · 不合格≠必退
主线流程 · 一进三出
流程速览：先甩结论——"不合格不一定退货，能修的修一把"，再讲三条出口（晒干/过筛返工复检、直接退货、复检仍不合格退货）。这是中药饮片行业特有的 物理返工，一般 ERP 没这功能。
1
一句话目的
把"检验不合格但还能救"的物料救回来：通过物理返工（晒干降水分、过筛除杂质）+ 只复检不合格项目，让物料重新走回放行入库，避免不必要的退货损失；确实救不了的才退货。
2
触发条件
检验结果登记时发现物料不符合规定——只要有一条不符合规定，这批就是不合格品，就会进入物料检验不合格处理单。接采购流程（业务流程 01）的检验环节。
3
前置 / 上游
① 物料检验结果单已登记，且有不合格项
② 常规流程对比：老做法是"先生成检验报告单 → 入库 → 退货"；新增功能允许先不走检验报告单流程，在不合格处理单里先处理——流程更短
4
主线步骤（一进三出）
① 物料检验不合格处理单：提取物料检验结果单，有过一条不合格项就在这里处理 → 选处理措施：晒干 / 过筛 / 退货
出口 A · 返工复检后放行（晒干 / 过筛）
② 线下实际执行处理措施 → 其他检验项目任务下达（只勾不合格的项目重检，不用全做；返工后不再走取样流程，直接下达）
③ 其他检验项目结果登记 → 符合规定 → 其他检验项目结果审核 → 审核通过
④ 回到物料检验报告单：重新提取收货验收单（能看到之前不合格物料的单子）→ 因复检均符合规定 → 生成检验报告单 → 物料放行单 → 放行 → 正常入库可用
出口 B · 直接退货（措施选退货）
⑤ 检验报告单里重新生成不合格检验报告单 → 审批 → 物料不放行 → 入库 → 不合格登记单登记 → 走采购退货流程
出口 C · 复检仍不合格
⑥ 在物料放行单里提取原检验报告单 → 选质量不放行 → 入库 → 不合格登记单登记 → 走采购退货流程

关键单据与字段
物料检验不合格处理单：处理措施（只有三种：晒干 / 过筛 / 退货）、提取的物料检验结果单；本单不需要审批
其他检验项目任务下达：只勾不合格的检验项目（核心控制点）、返工后不取样
其他检验项目结果登记 / 审核：复检结论
物料检验报告单：重新提取收货验收单 / 提取原物料检验结果登记单｜物料放行单：放行 / 质量不放行（质量负责人）
不合格登记单：只记录已入库物料的不合格——品名 / 批号 / 数量 / 不合格原因 / 处理方式

6
异常与回退
复检仍不合格 → 物料放行单选"质量不放行" → 入库 → 不合格登记单登记 → 采购退货流程
处理措施选退货 → 生成不合格检验报告单 → 审批 → 不放行 → 入库 → 不合格登记单登记 → 采购退货流程
单据做了但线下没实际处理 → 复检照样不合格——单据与实物必须一致（GMP 检查重点）
不合格品在出结果前 → 物理上隔离，绝不能用于生产
7
下游衔接
返工复检合格 → 正常入库可用（接生产领料）；退货 → 接采购退出流程（业务流程 02）；处理措施=退货的记录会触发采购退货预警（按采购订单关联）。
客户信管检查点（上线后要盯的 四 点）

① 不合格处理单和检验报告单什么关系？ → 处理单是"先处理、后出报告"的快捷通道：先定处理措施、线下返工、复检合格，再回报告单生成合格报告放行。避免了不合格就一路走到底退货。

② 为什么复检只做不合格项目？ → 返工只影响出问题的那几个指标（比如水分、杂质），其他项目不受影响，全做纯属浪费人力和时间——这叫针对性复验。

③ 晒干 / 过筛算什么性质？ → 属于 返工：中药饮片很多不合格是物理指标（水分、杂质），不是内在质量缺陷，物理手段能修正；修正后重新检验合格即可放行，但要留记录、要复检。

④ 哪些不合格救不回来？ → 霉变、虫蛀、有效成分含量不达标、有毒有害物质超标这类内在质量缺陷，物理手段救不了——只能退货（或销毁）。

关键结论

① 初验不设检验项目：初验在系统里不维护检验项目，全靠现场 QA 目视判断；系统只有状态——初验状态（合格 / 拒收 / 待处理）+ 来料状况（需处理 / 无需处理 / 处理中）。合格 = 正常走流程、对应"无需处理"；不行就"拒收"。

② 处理措施只有三种：晒干 / 过筛 / 退货。

③ 返工后不做取样流程：直接"其他检验项目任务下达 → 结果登记 → 结果审核"。

④ 物料检验不合格处理单不需要审批。

⑤ 不合格登记单适用范围：物料检验不合格 + 其他检验不合格（复检）；初验拒收的不进——它只记录已入库的物料。其他检验结果审核后，会在物料检验单里提取原来的物料检验结果登记单。

⑥ "待处理 / 需处理 / 处理中"这几个中间状态，交付后由客户企业信管自行补充。

为什么"晒干 / 过筛"能救回来 · 详解

这条流程的行业内核——讲明白了，读者能看清中药饮片
关键区分：物理指标不合格（水分、杂质）可以返工修正；内在质量不合格（霉变、成分不达标）只能退。
5
一句话内核
能修的修，修好了复检，修不了的退。
晒干：中药材水分超标 → 晾晒/烘干降水分 → 复检水分合格 → 放行
过筛：杂质（泥沙、碎屑）过多 → 过筛除杂 → 复检杂质合格 → 放行
为什么合理：GMP 对"不合格品能否处理后再用"是有严格前提的——不影响产品质量、符合质量标准、按预定的经批准操作规程、经风险评估后，才允许处理，且全程要有记录（GMP 第134条思路）。中药饮片的"晒干/过筛"针对的是物理指标（水分、杂质），不是内在质量缺陷，符合这个前提，所以能修；修完复检合格才能放行，复检不合格一律退货。
为什么值得讲：一般 ERP 系统只有"合格/不合格"两个结果，你们这套多了"返工复检"这条路——这是中药饮片行业的工艺特点落在系统里的体现
06业务流程 06 · 质量复验流程
业务流程 06 · 质量复验流程（在库超期复检） 模块：质检 → 仓储 → 财务 · 到期触发 · 不合格走报损销毁
主线流程 · 一进两出
流程速览：先讲为什么有这条流程（在库久了会变质，等于"养护"），再讲主线（请验→取样→留样→检验→审核→报告单→放行），最后讲不合格那条岔路（不是退货，是报损销毁）。
1
一句话目的
对在库时间较长的物料（原料/辅料/包材）和成品，按复验周期定期重新检验，确认是否仍符合质量标准——合格的继续投产/销售，不合格的报损销毁，防止变质物料流入生产或卖给客户。
2
触发条件
库存时间达到复验周期：该批次还没复验过（系统里有"未复验"标记）且 复验检验日期 = 物料入库时间 + 复验周期。由仓储人员发起复验请验单。
（复验周期在基础资料维护：物料/成品建档时填 复验周期 + 单位，一般 x 年）
3
前置 / 上游
① 物料/成品基础资料已维护复验周期 + 单位（x 年）
② 该物料/成品已入库放行（在库状态）——上游接采购入库（卡 01）或生产入库（卡 03）
③ 有对应质量标准（决定复验项目）
4
主线步骤（一进两出）
① 复验请验单（仓储人员发起）→ ② 复验取样单（取样员：填取样数量、确认复验品种）→ ③ 复验留样单（留样员：确认留样数量、检验数量、商品明细批号）
④ 复验检验项目确认 → ⑤ 复验检验项目任务下达（不同任务分发不同检验人 + 审核人）→ ⑥ 复验检验结果登记（检验人填检验结果 + 检验结论）→ ⑦ QC 主管审核 → ⑧ 复验检验报告单（提取检验结果登记单）
出口 A · 复验合格
⑨ 质量复验放行 → 通过 → 继续在库使用（物料接生产领料 / 成品可销售）
出口 B · 复验不合格
⑩ 也是正常审核通过 → 在质量复验放行里选 "质量放行不通过" → 🔴 第一时间发起"商品批号停售 / 商品停售"（先禁售，把风险掐住）→ 不合格登记单登记 → 损溢开票单（库存报损）→ 审批（🔴 审批链不固定，按客户实际业务需求配置；常见 3～5 级：仓储/采购/质量经理 → 质量负责人 → 总经理）→ 损溢执行单（库存数量 −、金额 −）→ 不合格药品销毁单（销毁人 + 监督人双签，GSP 留档）
5
关键单据与字段
基础资料：复验周期 + 单位（x 年）
批次复验标记：未复验 / 已复验（决定这批还要不要走复验）
复验请验单：复验检验日期（= 入库时间 + 复验周期）｜取样单：取样数量｜留样单：留样数量、检验数量、商品明细批号
结果登记：检验结果 + 检验结论｜报告单：提取检验结果登记单
商品资料：复验周期 + 单位、取样量、留样量（都能在商品资料里维护，不用写死）
损溢开票单 / 执行单：库存数量、库存金额（这两个都减）——执行单是真正动库存的动作，开票单只是开单
不合格药品销毁单：销毁日期、销毁原因、销毁方式、销毁地点、销毁人、监督人（销毁不是随手扔，要留档、要双人）
6
异常与回退
复验不合格 → 质量复验放行选"不通过" → 🔴 先发起商品批号停售 / 商品停售 → 不合格登记单 → 损溢开票单 → 多级审批 → 损溢执行单（库存 + 金额双减）→ 销毁
🔴 停售是第一动作：复验发现不合格（成品），要第一时间发起"商品批号停售"（只停这一个/几个批号）或"商品停售"（整个品种全停），选停售品种、（批号）、停售开始时间与结束时间。停售期内该品种/批号不参与任何销售流程，批号停售的批号在销售开票单里不显示——先掐住销售口，再走报损销毁（详见业务流程 07）
🔴 关键区别：复验不合格不是退货，是报损——货是自己的库存、已过供应商责任期，损失自己承担，所以要走损溢（报损）流程，而不是采购退出
为什么审批这么重（5 个角色）：涉及库存数量减少 + 库存金额减少，是资产损失，必须有授权链
不合格品在处置前 → 物理隔离，绝不能用于生产或销售
7
下游衔接
复验通过 → 继续在库（物料接生产领料、成品接销售出库）；复验不合格 → 报损销毁 → 库存与金额同步减少，财务做资产损失处理；成品在库久了会影响销量、增加退货量，复验是库房质量管理的手段。
客户信管检查点（上线后要盯的 五 点）

① 复验和来料检验的区别？ → 对象和责任方不同：来料检验检的是"刚到货的物料"，在供应商责任期内，不合格可以退；复验检的是"在库超期的物料/成品"，是自己的库存，不合格只能报损销毁。

② 复验靠什么触发？ → 商品资料里维护的复验周期（x 年）+ 该批次"未复验"标记 + 日期对得上（复验检验日期 = 入库时间 + 复验周期）→ 系统自动预警，仓储发起请验。

③ 为什么复验不合格要走损溢而不是退货？ → 货已入库且过了供应商责任期（很多是自身存储时间久导致），属自己的资产损失，必须走报损审批（多级，按客户配置）+ 损溢执行，最后销毁。而且第一动作是先发起"商品批号停售 / 商品停售"——先把销售口掐住，再走报损。

④ 为什么不合格也是"正常审核通过"？ → 权限分层，跟采购检验一个逻辑：审核环节只核"检验做没做完"，放行环节才是否决点（质量复验放行选不通过）——流程要留完整记录，不能卡在中间。

⑤ 损溢执行后库存怎么动的？ → 库存数量减、库存金额也减，两个方向同步减（这也是为什么审批重——动的是资产，不只是数量）。执行完再走销毁。

关键结论

① 到期提醒：✅ 有系统自动预警。

② 损溢审批链：✅ 不固定——按客户实际业务需求配置，不是写死的 5 级。讲的时候说"多级审批、按客户配"，别说死。

③ 复验留样：✅ 要留样；留样量、取样量都在商品资料里维护，不写死在流程里。

④ 损溢执行后库存怎么冲：✅ 库存数量与金额同步减少（损溢是系统标准动作，方向固定）。

来料检验 vs 在库复验 · 对比

这条流程最容易考混的地方——两条检验链，四个维度都不同
一句话：来料检验管"进门"，复验管"在库"。前者不合格能退给供应商，后者不合格只能自己认损。
维度 来料检验（卡 01 / 05） 在库复验（卡 06）
检验对象 刚到货的原料/辅料/包材 在库超期的物料 + 成品
触发方式 到货收货后启动（事件驱动） 达到复验周期（时间驱动，看批次"是否已复验"标记）
不合格归属 供应商责任 → 退货（采购退出） 自身库存损失 → 报损（损溢）销毁
能否返工救回 能（晒干 / 过筛 + 复检合格放行） 流程未体现返工，直接走报损
单据链 请验→取样→留样→检验→报告单→放行单 请验→取样→留样→检验→报告单→复验放行→损溢
目的 合格物料才能进生产（源头控制） 防变质物料流入生产/销售（库房养护）

复验触发条件 · 详解

这张卡最容易考混——"什么时候该复验"到底是怎么判出来的
复验是时间驱动的流程：不是谁想起来才做，而是系统按周期到点提醒。两个条件同时满足才触发。
要素 内容
条件一 还没复验过：该批次未复验（系统里有"未复验"标记）
条件二 时间到点：复验检验日期 = 物料入库时间 + 复验周期
周期从哪来 商品资料建档时维护的 复验周期 + 单位（一般按年）——配在资料里，不写死在流程里
谁提醒 / 谁发起 到点后系统自动预警；由仓储发起复验请验单
一句话总结怎么讲：商品资料里设了复验周期 → 货在库躺到那个时点 → 系统自动预警 → 仓储发起复验请验单。周期是资料配的，时点是系统算的，发起人是仓储。

GMP 在库复验 vs GSP 质量复查 · 对象完全不同

同样是"质量复查"四个字，GMP 和 GSP 指的是两码事——这是最容易讲混的地方
一句话：GMP 的质量复验针对"库存商品"（时间驱动、在库久了要重新检），GSP 的质量复查针对"验收"（事件驱动、货进来时判合格/待处理/不合格）。
维度 GMP 质量复验（本卡主线） GSP 质量复查（经营企业）
对象 库存商品（物料 / 成品，在库超期） 验收环节（采购到货验收、销售退回验收）
触发 时间驱动：在库时间达到复验周期 事件驱动：货到、待验收时
判什么 是否仍符合质量标准 → 合格继续用 / 不合格报损销毁 验收三态：合格 / 待处理 / 不合格 → 合格入库、待处理挂起、不合格进不合格登记
谁来判定 检验人 → QC 主管审核 → 质量负责人放行 验收员初判 → 质量专员提待处理单 → 质量主管 / 经理判定
不合格去向 报损销毁（自己的库存损失） 验收不合格 → 拒收退回上游（采购）/ 不合格登记（销售退回）
为什么会有这个差别：GMP 是生产企业，货生产出来后要在自己库里放很久，所以要"在库复验"防变质；GSP 是经营企业，货买进来转手就卖，不长期囤积，所以质量把关的重点放在货进来时的"验收"这一道关上，没有"在库超期复验"这一套。

GSP 质量人员体系 · 专员 / 主管 / 经理 / 负责人

一个合格 GSP 企业的质量，不靠某个流程，靠一整套质量人员各司其职
一句话：质量人员可能不负责某个具体流程的操作，但停售停采、不合格、验收待处理这些环节，处处都有质量人员的影子——离了这套体系，GSP 就立不住。

（质量管理员）		 一线的质量执行者：日常验收、质量信息收集、质量档案建立、养护技术指导 采购验收待处理时提待处理单；发现质量异常报质量主管
质量主管 质量部门的日常负责人：审核质量记录、组织验收判定、处理一般质量问题 待处理判定、不合格登记的审核、停售停采的发起与审核
质量经理 质量部门负责人：组织质量管理体系运行、内审、风险评估、对接药监 重大质量问题的处理、商品停售 / 停采、不合格、召回的组织
质量负责人 企业高层，执业药师 + 3 年以上经验，独立履行职责、有质量裁决权，全面负责质量 所有质量放行 / 否决的终判；不合格销毁、召回、质量事故的最终签字
质量人员在这些流程里的参与（不亲自操作，但处处把关）
流程 质量人员的角色
商品批号停售 / 停采 质量人员发起停售停采判定，确认不合格 / 有问题后才禁；仓储、采购只是执行停售结果
商品停售 / 停采 整个品种的停售停采，由质量经理 / 质量负责人决定，涉及面更大、层级更高
不合格流程 不合格的确认、登记、监督处理都是质量部门的职责（GSP 规范第 17 条第 6 项）；报损销毁需质量负责人签字
验收待处理 质量专员提待处理单 → 质量主管 / 经理判定合格与否，再分流入库或退货
药品召回 / 不良反应 质量部门负责召回管理和不良反应报告（GSP 规范第 17 条），质量负责人牵头
一句话怎么讲：质量人员可能不亲自录单、不亲自拣货、不亲自收款——他们不负责某个具体流程的"操作"，但停售停采、不合格、验收待处理、召回这些环节的"判定"和"把关"都离不开质量人员。一个合格的 GSP 认证企业，一定有一套完整的质量人员体系（专员 → 主管 → 经理 → 负责人），缺一环都不行。
GSP 的硬性要求（参考 GSP 规范第 13～21 条）：企业要设独立的质量管理部门，质量管理部门职责不得由其他部门或人员代替；质量负责人须在职在岗、有质量裁决权。所以这不是"可有可无的岗位"，是认证的刚性门槛。
07业务流程 07 · 销售流程GMP 版
业务流程 07 · 销售流程 模块：销售 → WMS → 财务 · 企业最终目的：营收
主线流程
流程速览：先立住为什么销售是最重要的流程——采购是买料、生产是把料变成能卖的商品、质量是对物料/客户/自己/消费者负责，而销售是把前面所有投入换成钱的那一步。再讲骨架（订单 → 开票单 → WMS 拣货复核 → 出库单），最后讲开票单上的几道自动校验和两种改单方式。
1
一句话目的
把仓库里检验合格的成品按客户需求卖出去、把钱收回来——这是企业最终目的所在。上游一切（采购物料、加工生产、质量检验）都在为这一步做铺垫：采购对生产负责、生产对销售负责、质量对物料负责、对客户负责、对自己负责、对消费者负责。
2
触发条件
客户下单：从客户处接到销售订单合同或电话采购。
谁发起：销售外勤 / 销售主管 / 销售经理（一般是销售外勤）。
谁做单：实际录系统的是销售开票员——发起人和做单人不是一个人，这点最容易混淆。
3
前置 / 上游
① 成品已生产检验放行、已入库（接业务流程 03 生产入库）
② 🔴 客户必须是已完成"首营资料"的客户——没做首营的客户，在销售订单 / 销售开票单里根本选不出来。不是在出库那一步才拦，是从源头就选不到，从根上杜绝了给不合规客户发货的可能
③ 客户资料已维护：客户等级、客户类型、所属区域、付款方式、发票类型、开户银行信息、实际收货地址、经营范围、信贷额度、收款方式（应收账款 / 现金）
④ 一品多价已维护且录了启用时间（不录启用时间不生效）
⑤ 该品种 / 该批号未被停售
4
主线步骤（四步骨架）
① 销售订单（销售外勤发起）——无视库存，不校验成品库存；只选系统里的成品；可以指定批号（客户没指定就不填）；可以指定专门库房（给某个客户定制一个成品库房，他要的货都从这个库出，便于管理）；录数量、价格。
② 分流：有库存 → 直接做销售开票单；没库存 → 挂在销售订单里等——客户不着急或者有规定到货日期就先挂单，系统有预警，等对应品种入库后预警销售开票员去做开票单。
③ 销售开票单（两种做法：提取销售订单 或 直接开销售开票单）——从订单带出商品/数量/价格，系统自动分摊库存批号；抬头确认开户银行信息、发票信息、付款方式、物流信息、实际收货地址。
④ WMS 拣货、复核：销售开票单下发仓库后，仓储在手持设备上作业——按 FIFO 先进先出拣货（系统按批号自动推荐），拣完复核人二次确认；拣货和发货可以是同一个人（单独库房只有一个负责人的情况），但复核这道确认不能省。详见卡 10（WMS 仓储作业）
→ ⑤ 销售出库单：直接提取销售开票单，保存出库，对应商品数量减少。
🔴 出库这一步是"不可回头"的分界线：一旦出库、系统里生成了出库单据，这张开票单就改不动了（见第 6 问）。
5
关键单据与字段
销售订单：成品品种、数量、价格、指定批号（可选）、指定库房（可为客户定制）｜⚠️ 不校验库存
销售开票单：自动分摊的批号与数量、开户银行信息、发票类型、付款方式、物流信息、实际收货地址（客户可能有多个仓库）、审核状态
销售出库单：直接提取销售开票单、出库数量（保存后库存减少）
基础资料（维护好就自动带出）：付款方式、发票类型、开户银行信息、实际收货地址
6
异常与回退
改单：先看有没有出库
🔴 已经出库、系统里已经生成出库单据的——这张单就没有 "改" 这个选项了，只有一条路：走销售退回流程把整张单全部退掉，然后重新走开票流程。没有第二条路。（这也是为什么开票员宁可在出库前多确认两遍。）
反审修改（还没出库）：单子开了但没出库，客户要加品种且要求在同一张单上 → 到功能单据反审里反审核 → 在销售开票单里找单据调整选中改 → 重新保存后再次进入 WMS 拣货、复核、出库。
暂存（还没出库、客户还在翻来覆去改）：把刚生成的销售开票单选中"暂存"，此单不进行审批、审核状态不变，要调就在单据调整里改。
开票单会被卡住 / 要审批的情况
① 经营范围不匹配：客户经营范围是"中药饮片"，要卖"毒性中药饮片"→ 选商品时自动拦截，不让保存
② 一品多价匹配不到：客户等级 / 类型 / 区域没命中价格（或没录启用时间）
③ 批号停售 / 商品停售：停售期内不参与任何销售流程；批号停售的批号在开票单里不显示
④ FIFO 提醒：销售数量大于最老批号的库存量、导致没用老批号 → 弹提醒："未选择先进先出产品"且必须填写未选择的原因
⑤ 账期校验 / 信贷额度校验不通过 → 进入审批（销售经理审批）
7
下游衔接
出库 → 配送 → 客户签收 / 回单：走物流配送单 + 配送回执单（详见下方专题卡）
出库 → 库存减少 → 财务收款（应收、回款核销，见卡 09 销售收款）
客户退货 → 销售退回流程（卡 08）；金额差异 → 销售冲差 / 退补
已出库还想改单 → 同样只能倒着走卡 08：整单全退 → 重新开票。所以 07 和 08 是互为出口的一对卡。
与采购、生产的联动（逆推链）：品种库存低于最低库存 / 生产指令缺物料 / 销售计划缺产品库存 → 逆推到生产指令 → 再由生产指令逆推到采购计划。
⚠️ 但有几条不发起的情况：成品不足但半成品充足 → 不发起采购计划；成品足、但半成品 / 物料不足 → 也不发起采购计划。
客户信管检查点（上线后要盯的 六 点）

① 销售订单为什么不校验库存？ → 它是"客户要什么"的记录，不是发货指令。没库存可以先挂单，系统有预警，等品种入库后提醒开票员做开票单。

② 销售开票单和销售出库单什么关系？ → 开票单定"卖什么、多少、哪个批号、什么价"，出库单直接提取开票单；真正减库存是在出库那一步。

③ 开票单里的批号怎么来的？ → 系统自动分摊：优先分摊数量少的、批号靠前的。例：开 A 品种 1000 个，库存 a1 批号 300 + a2 批号 800 → 分摊 a1 的 300 + a2 的 700。

④ 客户要改单怎么办？ → 先看有没有出库。没出库：反审 → 单据调整 → 重新保存；客户反复改：先暂存（不审批、审核状态不变）；已经出库、生成了出库单据：只能整单走销售退回流程全退掉，再重新开票，没有别的路。

⑤ 什么情况会卡住不让保存？ → 经营范围不匹配（毒性饮片 vs 中药饮片）/ 一品多价没匹配到 / 批号或商品停售。

⑥ 开票单什么时候要审批？ → 账期校验（客户逾期回款）+ 信贷额度校验（超出可用额度）→ 销售经理审批。

补充说明

✅ WMS 拣货、复核环节：手持作业、按 FIFO 拣货、复核人二次确认、拣货与发货可为同一人 → 详见卡 10；一品多价三维度优先级见上方专题卡；销售出库要复核人二次确认；没做首营的客户选不出来。

✅ 挂单预警：发给销售开票员（不具体指定到某个人），提醒方式为系统消息预警；品种入库后预警开票员做开票单。

✅ 停售时已卖出去的货：按药品召回处理，参照 GMP 对已上市药品召回的规定（质量部门评估发起，召回产品登记、隔离、评价处理）。

销售开票单 · 四道自动校验

开票单上"系统自动拦你"的四个点，接手维护时最常被问到
一句话：能不能卖、卖什么价、用哪个批号、这个批号还能不能卖——四道各管一件事。
校验 触发条件 系统动作
① 经营范围 客户经营范围与所售品种不匹配（如客户是"中药饮片"，要卖"毒性中药饮片"） 提取订单 / 选商品时自动拦截，不让保存
② 一品多价 同一商品面对不同区域 / 不同类型（医院、医疗机构、诊所）/ 不同等级的客户，价格不同 选商品和批号时，按客户等级 + 客户类型 + 区域自动匹配对应售价
③ 先进先出 FIFO 销售数量大于最老批号的库存量，导致没有选择老批号 弹提醒："未选择先进先出产品"，且必须填写未选择的原因
④ 停售 该品种或该批号在停售的时间区间内 停售期内不参与任何销售流程；批号停售的批号在开票单里不显示
为什么生产企业特别强调 FIFO：生产企业的最终目的是有营收，产出来的货当然要先把批号老的（早的）卖掉，再卖新批号——老批号压在库里越久，效期压力越大、越容易报废。

一品多价 · 怎么维护、怎么生效、怎么定优先级

目的：解决不同区域、不同类型、不同等级客户的价格差异
ERP 有一品多价维护功能，维护顺序：先选商品 → 再选区域 / 等级 / 客户类型 / 销售价格 / 启用时间。
!
🔴 最容易踩的坑：启用时间
如果不录入启用时间，就算前置条件维护得再好也不生效——这是实施和客户培训最常被漏掉的一步。
另外区域、客户类型、客户等级这三样是在客户资料维护功能里维护的，不是在一品多价里现填。
📌 一个重要背景（行业常见差异）：ERP 标准的一品多价往往只有"客户等级"这一个标准，所属区域和回款周期这两个维度是根据客户业务需求做的扩展。所以讲的时候要分清楚：哪些是标准功能、哪些是项目定制扩展——接手维护时这一点最要注意。
优先级 命中的维度组合 说明
最高 客户等级 + 所属区域 + 回款周期 三个维度全部命中，取价最精准
次高 客户等级 + 所属区域 或 客户等级 + 回款周期 两两组合，命中哪组用哪组
兜底 所属区域 + 回款周期 退到最宽的一档（不含客户等级）
优先级怎么记：维度命中得越多越优先；同样多的，带"客户等级"的优先。
客户等级 > 区域 / 回款周期 —— 因为等级是这个项目原有的老标准，区域和回款周期是后加的两个新维度，取价时等级的分量更重。

批号停售 vs 商品停售 · 差几个字，范围天差地别

这两个功能名字很像，接手维护时最容易被拿来对比
功能 停售范围 操作
商品批号停售 只停这个品种的某一个 / 某几个批号 选停售品种 → 选批号 → 选停售开始时间、结束时间
商品停售 停整个品种，所有批号都不能卖 选停售品种 → 选停售开始时间、结束时间
什么时候发起：一般在复验流程和养护流程中——发现成品的某个批号不合格、或整个品种不合格，要第一时间发起停售（生产企业只能销售成品，不销售物料和半成品）。
停售效果：类似"禁售"。停售后，该品种 / 该批号从开始时间到结束时间不参与任何销售流程。
停售时已经卖出去的货怎么办：按药品召回处理——参照 GMP 对已上市药品召回的规定，由质量部门评估发起召回（召回的产品按 GMP 要求登记、隔离、评价处理）。
🔗 已同步补进业务流程 06（质量复验流程）：复验不合格 → 先发起商品批号停售 / 商品停售 → 再走不合格登记、损溢报损、销毁。

开票单的特殊审核 · 账期 + 信贷额度

这是"什么情况下开票单不用审、什么情况下必须销售经理审"的判定逻辑
销售开票单默认没有审核——开完单之后审核状态自动变成"已审核"，直接开单。只有这两种校验不通过时，才进入审批流程（销售经理审批）。
1
账期校验
账期从出库单日期开始算，一般是 30 天 / 60 天 / 90 天，或按企业设定。
算法：该客户上次出库单日期 + 账期天数 得到应回款日，拿它跟客户回款日期比——
· 应回款日 晚于 实际回款日 → 客户按时 / 提前回款 → 不审批，直接开
· 应回款日 早于 实际回款日 → 客户逾期回款 → 进入审批（销售经理）
2
信贷额度校验
开票员在客户资料里维护该客户的信贷额度（如 30000）。校验逻辑是：看客户之前所有开票单的金额，在账期内有没有回款。
举例：A 客户信贷额度 30000
· 第一次开单 10000、第二次开单 15000，都没回款 → 已占用 25000 → 第三次最多只能开 5000
· 如果账期内回款 20000 → 可用额度 = 30000 − 10000 − 15000 + 20000
· 发生退货单也做加法（退货等于把占用释放回来）
· 第三次开单金额 大于 5000 → 进入审批流程

开票单要改怎么办 · 三条路（先看有没有出库）

判断的第一刀不是"客户要改什么"，而是"这单出库了没有"
🔴 记住这条分界线：出库之前，单还能改；出库之后，单就是死的——因为库存已经真的减了、出库单据已经生成了。
方式 适用场景 操作路径
反审修改 单已开、但还没出库，客户要求增加品种、且要求在同一张单上 功能单据反审 → 反审核 → 销售开票单里找单据调整 → 选中该单修改 → 保存 → 重新进 WMS 拣货、复核、出库
暂存 客户翻来覆去改要的品种，单子还在拉扯中（也必须还没出库） 把刚生成的销售开票单选中"暂存" → 此单不审批、审核状态不变 → 要调在单据调整里改
全退重开
（唯一出路）		 🔴 销售开票单已经做了出库操作、系统里已经生成出库单据，客户还要改这张单 走销售退回流程把整张单全部退掉（卡 08）→ 然后重新走一遍开票流程。没有第二条路。
三者关系：反审是"已经审核生效了，退回未审状态再改"；暂存是"干脆卡在未审批状态，等客户定了再说"——两者共同点：都在出库之前，都要通过"单据调整"改，都不能直接改已生效的单。
全退重开是出库之后唯一的办法，代价最大：要走一遍完整的退回流程（通知单 → 收货单 → WMS 验收 → 退回入库单），再重新开票、重新出库。

客户签收 / 回单 · 配送回执单 + 物流配送单

货发出去之后，怎么盯到"客户真的收到了"
销售链路的最后一段是"货到了没有"：销售出库单只能证明"我发了"，配送回执单才能证明"客户收了"。
功能 干什么用的
物流配送单 登记这一趟配送的全部信息：司机、司机联系方式、物流信息（物流单号 + 快递公司）、销售出库单信息、客户信息
配送回执单 对应客户签收 / 回单环节——确认客户确实收到货了（万一有"客户说没收到"的争议，这就是凭证）
表单设计（抬头 / 明细怎么放）——这个设计本身也是考点：
· 抬头放客户信息（客户编号、客户名称、收货地址、联系人、联系方式）和司机信息——"这一趟送给谁、谁去送"
· 明细放该客户对应的销售出库单——"这一趟送的是哪几单货"
为什么这么放：抬头是这一趟配送的"共同属性"（谁、谁送），明细是会变的部分（送几张单）。
07业务流程 07 · 销售流程GSP 版
业务流程 07 · 销售流程 GSP 版 模块：销售 → WMS → 财务 · 企业最终目的：营收
主线流程
流程速览：GSP 经营企业没有销售订单，也没有 FIFO 先进先出提醒——核心逻辑是「必须有货才能卖」：客户下单后直接录销售开票单（不提取订单），下发拣货单到 WMS，仓储手持拣货复核，最后出库。骨架是「开票单 → 拣货单下发 → WMS 拣货复核 → 出库单」，比 GMP 少了「销售订单」和「FIFO 提醒」两环。
1
一句话目的
把仓库里已验收、已上架的合格商品按客户需求卖出去、把钱收回来——经营企业的最终目的所在。上游采购（收货、验收、上架）都在为这一步做铺垫。跟 GMP 生产企业最大的不同：经营企业是"先有货、再卖货"，不存在"没货先挂单"的说法。
2
触发条件
客户下单：从客户处接到销售合同或电话采购。
谁发起：销售外勤 / 销售主管 / 销售经理。
谁做单：实际录系统的是销售开票员。
🔴 GSP 与 GMP 的关键差异：GMP 生产企业的第一步是「销售订单」，无视库存、可以先挂单等货；GSP 经营企业没有销售订单，必须有货才能销售——客户下单后，销售开票员直接录销售开票单，录的时候就校验库存，没货根本录不进去。
3
前置 / 上游
① 商品已采购收货、验收合格、已上架（接卡 01 采购流程，GSP 版）
② 🔴 客户必须是已完成"首营资料"的客户——没做首营的客户，在销售开票单里根本选不出来，从根上杜绝给不合规客户发货
③ 客户资料已维护：客户等级、客户类型、所属区域、付款方式、发票类型、开户银行信息、实际收货地址、经营范围、信贷额度、收款方式（应收账款 / 现金）
④ 一品多价已维护且录了启用时间（不录启用时间不生效）
⑤ 该品种 / 该批号未被停售
4
主线步骤（四步骨架）
① 销售开票单（销售开票员直接录，不提取销售订单）——必须有库存，录单即校验库存；只选系统里的商品；选批号、录数量、价格。抬头确认开户银行信息、发票信息、付款方式、物流信息、实际收货地址。
② 下发拣货单：销售开票单下发拣货任务——在 ERP 或 WMS 中做拣货单任务下发，系统自动分摊到手持设备（跟采购退货的拣货逻辑一样，仓储人员在手持上就能看到自己该拣的货）。
③ WMS 拣货、复核：仓储在手持设备上按拣货单作业——没有 FIFO 先进先出提醒（这是 GMP 生产企业的专属校验，经营企业不做）；拣完复核人二次确认；拣货和发货可以是同一个人，但复核这道确认不能省。详见卡 10（WMS 仓储作业）。
→ ④ 销售出库单：直接提取销售开票单，保存出库，对应商品数量减少。
🔴 出库这一步是"不可回头"的分界线：一旦出库、生成了出库单据，这张开票单就改不动了（见第 6 问）。
5
关键单据与字段
销售开票单：商品品种、数量、价格、批号、开户银行信息、发票类型、付款方式、物流信息、实际收货地址（客户可能有多个仓库）、审核状态｜⚠️ 必须有库存才能录
拣货单：由开票单下发生成，自动分摊到手持设备，明细是「谁在哪拣哪个货位的哪批货」
销售出库单：直接提取销售开票单、出库数量（保存后库存减少）
基础资料（维护好就自动带出）：付款方式、发票类型、开户银行信息、实际收货地址
🔴 与 GMP 的字段差异：GMP 有「销售订单」这一层，开票单是自动分摊库存批号；GSP 没有销售订单，因此没有"自动分摊"这个动作——批号在录开票单时直接选定，拣货单按所选批号生成。
6
异常与回退
改单：先看有没有出库
🔴 已经出库、系统里已经生成出库单据的——这张单没有 "改" 这个选项了，只有一条路：走销售退回流程把整张单全部退掉，然后重新走开票流程。没有第二条路。
拣货环节的回退（GSP 特有，两条路）
· 拣货单已下发、还没拣货：走销售反审核流程，回到开票单改。
· 已经拣完货了也能改：先把手持设备上的货品数量回退到货位、回退拣货单，再走反审核改单。
暂存（还没出库、客户还在翻来覆去改）：把刚生成的销售开票单选中"暂存"，此单不进行审批、审核状态不变，要调就在单据调整里改。
开票单会被卡住 / 要审批的情况
① 经营范围不匹配（按 GSP 经营范围：客户经营范围与所售商品不匹配）→ 选商品时自动拦截，不让保存
② 一品多价匹配不到：客户等级 / 类型 / 区域没命中价格（或没录启用时间）
③ 批号停售 / 商品停售：停售期内不参与任何销售流程；批号停售的批号在开票单里不显示
④ 账期校验 / 信贷额度校验不通过 → 进入审批（销售经理审批）
7
下游衔接
出库 → 配送 → 客户签收 / 回单：走物流配送单 + 配送回执单（详见下方专题卡）
出库 → 库存减少 → 财务收款（应收、回款核销，见卡 09 销售收款）
客户退货 → 销售退回流程（卡 08）；金额差异 → 销售冲差 / 退补
已出库还想改单 → 同样只能倒着走卡 08：整单全退 → 重新开票。所以 07 和 08 是互为出口的一对卡。
客户信管检查点（上线后要盯的 六 点）

① 为什么 GSP 没有销售订单？ → 经营企业必须有货才能卖，客户下单直接录销售开票单，录单即校验库存，不存在"没货挂单等货"的情况。

② 销售开票单和销售出库单什么关系？ → 开票单定"卖什么、多少、哪个批号、什么价"，出库单直接提取开票单；真正减库存是在出库那一步。

③ 批号怎么定？ → 录开票单时直接选定批号，没有自动分摊（那是 GMP 有销售订单才有的动作）。

④ 拣货单是什么？ → 开票单下发拣货任务，在 ERP 或 WMS 里生成拣货单，自动分摊到手持设备，仓储按单拣货、复核。

⑤ 拣货环节改单怎么办？ → 没拣货：走销售反审核流程 → 回到开票单改；已拣完：先把手持货品数量回退到货位、回退拣货单，再反审核。出库后只能整单走退回（卡 08）。

⑥ 什么情况卡住不让保存？ → 经营范围不匹配（按 GSP 经营范围） / 一品多价没匹配到 / 批号或商品停售。

补充说明

✅ WMS 拣货、复核：手持作业、按拣货单拣货、复核人二次确认、拣货与发货可为同一人 → 详见卡 10。没有 FIFO 先进先出提醒——这是 GMP 生产企业的专属校验。

✅ 拣货单下发：在 ERP 或 WMS 中做拣货单任务下发，自动分摊到手持设备，跟采购退货的拣货逻辑一致。

✅ 开票单暂存：GSP 经营企业同样可以加暂存功能——把刚生成的开票单选"暂存"，此单不审批、审核状态不变，客户定了再在单据调整里改。

✅ 停售时已卖出去的货：按药品召回处理，参照 GSP 对已售药品召回的规定（质量部门评估发起，召回产品登记、隔离、评价处理）。

销售开票单 · 三道自动校验（GSP 无 FIFO）

开票单上"系统自动拦你"的三个点，接手维护时最常被问到
一句话：能不能卖、卖什么价、这个批号还能不能卖——三道各管一件事。注意：GSP 没有 FIFO 先进先出这道校验。
校验 触发条件 系统动作
① 经营范围 客户经营范围与所售商品不匹配（按 GSP 经营范围，如客户经营范围里没有该品类） 选商品时自动拦截，不让保存
② 一品多价 同一商品面对不同区域 / 不同类型 / 不同等级的客户，价格不同 选商品和批号时，按客户等级 + 客户类型 + 区域自动匹配对应售价
③ 停售 该品种或该批号在停售的时间区间内 停售期内不参与任何销售流程；批号停售的批号在开票单里不显示
为什么经营企业不做 FIFO：FIFO（先进先出）提醒是生产企业为了让「老批号先卖掉、缓解效期压力」而设的专属校验。经营企业（GSP）是"买进卖出"，商品的效期和批次由上游供应商决定，销售时不需要系统强制按先进先出提醒——所以这道校验在 GSP 里不启用。

一品多价 · 怎么维护、怎么生效、怎么定优先级

目的：解决不同区域、不同类型、不同等级客户的价格差异
ERP 有一品多价维护功能，维护顺序：先选商品 → 再选区域 / 等级 / 客户类型 / 销售价格 / 启用时间。
!
🔴 最容易踩的坑：启用时间
如果不录入启用时间，就算前置条件维护得再好也不生效——这是实施和客户培训最常被漏掉的一步。
另外区域、客户类型、客户等级这三样是在客户资料维护功能里维护的，不是在一品多价里现填。
📌 一个重要背景（行业常见差异）：ERP 标准的一品多价往往只有"客户等级"这一个标准，所属区域和回款周期这两个维度是根据客户业务需求做的扩展。所以讲的时候要分清楚：哪些是标准功能、哪些是项目定制扩展——接手维护时这一点最要注意。
优先级 命中的维度组合 说明
最高 客户等级 + 所属区域 + 回款周期 三个维度全部命中，取价最精准
次高 客户等级 + 所属区域 或 客户等级 + 回款周期 两两组合，命中哪组用哪组
兜底 所属区域 + 回款周期 退到最宽的一档（不含客户等级）
优先级怎么记：维度命中得越多越优先；同样多的，带"客户等级"的优先。
客户等级 > 区域 / 回款周期 —— 因为等级是这个项目原有的老标准，区域和回款周期是后加的两个新维度，取价时等级的分量更重。

批号停售 vs 商品停售 · 差几个字，范围天差地别

这两个功能名字很像，接手维护时最容易被拿来对比
功能 停售范围 操作
商品批号停售 只停这个品种的某一个 / 某几个批号 选停售品种 → 选批号 → 选停售开始时间、结束时间
商品停售 停整个品种，所有批号都不能卖 选停售品种 → 选停售开始时间、结束时间
什么时候发起：一般在复验流程和养护流程中——发现商品的某个批号不合格、或整个品种不合格，要第一时间发起停售。
停售效果：类似"禁售"。停售后，该品种 / 该批号从开始时间到结束时间不参与任何销售流程。
停售时已经卖出去的货怎么办：按药品召回处理——参照 GSP 对已售药品召回的规定，由质量部门评估发起召回（召回的产品按 GSP 要求登记、隔离、评价处理）。
🔗 已同步补进业务流程 06（质量复验流程）：复验不合格 → 先发起商品批号停售 / 商品停售 → 再走不合格登记、损溢报损、销毁。

开票单的特殊审核 · 账期 + 信贷额度

这是"什么情况下开票单不用审、什么情况下必须销售经理审"的判定逻辑
销售开票单默认没有审核——开完单之后审核状态自动变成"已审核"，直接开单。只有这两种校验不通过时，才进入审批流程（销售经理审批）。
1
账期校验
账期从出库单日期开始算，一般是 30 天 / 60 天 / 90 天，或按企业设定。
算法：该客户上次出库单日期 + 账期天数 得到应回款日，拿它跟客户回款日期比——
· 应回款日 晚于 实际回款日 → 客户按时 / 提前回款 → 不审批，直接开
· 应回款日 早于 实际回款日 → 客户逾期回款 → 进入审批（销售经理）
2
信贷额度校验
开票员在客户资料里维护该客户的信贷额度（如 30000）。校验逻辑是：看客户之前所有开票单的金额，在账期内有没有回款。
举例：A 客户信贷额度 30000
· 第一次开单 10000、第二次开单 15000，都没回款 → 已占用 25000 → 第三次最多只能开 5000
· 如果账期内回款 20000 → 可用额度 = 30000 − 10000 − 15000 + 20000
· 发生退货单也做加法（退货等于把占用释放回来）
· 第三次开单金额 大于 5000 → 进入审批流程

开票单要改怎么办 · 三条路（先看有没有出库）

判断的第一刀不是"客户要改什么"，而是"这单出库了没有"
🔴 记住这条分界线：出库之前，单还能改；出库之后，单就是死的——因为库存已经真的减了、出库单据已经生成了。
方式 适用场景 操作路径
反审修改 单已开、但还没出库，客户要求增加品种、且要求在同一张单上 功能单据反审 → 反审核 → 销售开票单里找单据调整 → 选中该单修改 → 保存 → 重新下发拣货单、拣货、复核、出库
拣货回退
（GSP 特有）		 拣货单已下发 / 已拣完货，但还没出库，客户要改 走反审核流程：未拣货 → 销售反审核回到开票单改；已拣完 → 先把手持货品数量回退到货位、回退拣货单 → 再反审核改单
暂存 客户翻来覆去改要的品种，单子还在拉扯中（也必须还没出库） 把刚生成的销售开票单选中"暂存" → 此单不审批、审核状态不变 → 要调在单据调整里改
全退重开
（唯一出路）		 🔴 销售开票单已经做了出库操作、系统里已经生成出库单据，客户还要改这张单 走销售退回流程把整张单全部退掉（卡 08）→ 然后重新走一遍开票流程。没有第二条路。
几者关系：反审是"已经审核生效了，退回未审状态再改"；拣货回退是"拣货单已经动起来了，先把货回退到货位、把拣货单退掉，再反审"；暂存是"干脆卡在未审批状态，等客户定了再说"——三者共同点：都在出库之前，都要通过"单据调整"改，都不能直接改已生效的单。
全退重开是出库之后唯一的办法，代价最大：要走一遍完整的退回流程（通知单 → 收货单 → WMS 验收 → 退回入库单），再重新开票、重新出库。

客户签收 / 回单 · 配送回执单 + 物流配送单

货发出去之后，怎么盯到"客户真的收到了"
销售链路的最后一段是"货到了没有"：销售出库单只能证明"我发了"，配送回执单才能证明"客户收了"。
功能 干什么用的
物流配送单 登记这一趟配送的全部信息：司机、司机联系方式、物流信息（物流单号 + 快递公司）、销售出库单信息、客户信息

08业务流程 08 · 销售退回 / 冲差流程GMP 版
业务流程 08 · 销售退回 / 冲差流程 模块：销售 → WMS → 仓储 · 销售的反向操作
主线流程
流程速览：跟卡 07 对着讲——销售是"货出去、钱进来"，退回是"货回来、账冲掉"。主线只有四步（通知单 → 收货单 → WMS 拣货验收 → 退回入库单），中间还挂着一条销售冲差 / 退补的支线专门处理"钱对不上"。
1
一句话目的
把客户退回的货收回入库，同时冲减对应的销售（数量、金额），让库存和应收都回到实际状态。跟采购退出（卡 02）是同一个道理，只是方向对着客户而不是供应商。
2
触发条件
客户提出退货——由销售侧发起销售退回通知单。
退货是分原因的，原因决定后面这货怎么处理，至少要分出两大类：
· 滞销 / 包装问题——货本身没质量问题，纯粹卖不动，或者包装不符合客户要求
· 质量问题——货本身有问题
原因在通知单上就要定下来，它直接决定验收之后货的去向：是重新上架继续卖，还是走不合格流程。
3
前置 / 上游
① 这批货已经销售出库过（上游接卡 07 销售流程的销售出库单）
② 客户已提出退货诉求（通知单的发起依据）
③ 退货要提取原销售出库单，由此带出三条硬约束：
· 退回数量 ≤ 原出货量——只能退当初发出去的那部分，不能多退
· 退回批号沿用原批号——批号在生产完成之后就一直跟着这批货，退货不改批号；退的就是当初发出去的那一批
🔴 唯一例外：企业收到退货后如果要"重新包装"，批号会重新生成——重新包装等于给这批货换了新身份，不再是原来那个批号
· 退回商品的单价不能变动——退货按原价冲回，不能借退货调价（真要调价走销售冲差）
🔴 还有一个前提：卡 07 里已经在系统里生成了出库单据的单要改，也只能走本流程——整单全退，再重新开票，这是唯一的出路。
4
主线步骤（四步）
① 销售退回通知单（销售侧发起，记录客户要退什么、什么原因）→ ② 销售收货单（仓库收货登记，收多少、哪个批号）→ ③ WMS 拣货、验收 → ④ 销售退回入库单（到此流程结束，货回到库里）。
③ 验收：目前系统里只有"外观判定"
🔴 退回检验通过线下 SOP 补位，目前由 QA 人员做外观判定——看包装有没有漏气、发潮、胀气这类问题，并留下评估记录。
⚠️ 但要注意：中药饮片的检验属于生产检验流程；而 GMP 第一百三十七条要求退货"经检查、检验和调查，有证据证明质量未受影响，并经质量管理部门评价后"才可重新包装、重新发运销售——所以只有外观判定，在 GMP 口径下是不完整的，至少要留下 QA 的评估记录（详见卡 10 的 GMP / GSP 专题卡）。
④ 按验收结果进哪个库
一般入合格品库——退回的货默认是能重新上架销售的；只有在外观判定中发现不合格或严重问题（漏气、发潮、胀气等）才入不合格品库，走不合格流程。
5
关键单据与字段
销售退回通知单：退货品种、数量、退货原因（决定货后续去哪）
销售收货单：实收数量、批号（沿用原批号）
销售退回入库单：入库数量、批号、入库库房（一般入合格品库；外观不合格 / 漏气·发潮·胀气 → 不合格品库）、退回单价（与原出货单价一致，不得变动）
提取的原销售出库单：带回原出货的品种、数量、批号、单价——退回数量受它约束（≤ 原出货量）
支线：金额差异
销售冲差单：申请 → 销售冲差执行（处理价格差、退补差价这类"数量不动、钱要调"的情况）
6
异常与回退
按退货原因分处理（本流程最重要的一岔）
① 滞销类（货没问题，卖不动 / 包装不符合客户要求）→ 重新上架继续销售；如果是包装问题，可以与客户协商换包装的成本，换好包装后重新上架。⚠️ 但一旦重新包装，批号就会重新生成——不再是原来那个批号
② 质量问题（货本身有问题）→ 入不合格品库 → 走不合格流程：不合格登记、必要时报损销毁（跟卡 05 / 06 同一套路数）；若属成品复验不合格，还要先发起商品批号停售 / 商品停售（卡 06）。
其他异常与红线
金额对不上 → 走销售冲差 / 退补（数量不动，只调金额）——注意它跟"退货"是两条并行的线，别混
想多退 / 想换批号 / 想改价 → 系统不允许：数量 ≤ 原出货量、批号沿用原批号、单价不得变动，这三条是硬约束
✅ 跨年退货财务怎么处理——（见卡末）：会计按"以前年度损益调整"调报告年度，税法一律在退货发生当期冲减。
7
下游衔接
退回入库 → 冲减销售 → 直接影响净销售口径（销出 − 退货），这也是销售业绩分析的口径基础
验收合格的退回品 → 回到可售库存（可能经重新上架 / 换包装再卖），等于把货"变回"能卖的状态
金额影响应收 → 退货会释放已占用的信贷额度（卡 07 信贷额度算法里：发生退货单是做加法）
不合格退回品 → 接不合格登记 / 损溢报损销毁（卡 05 / 06）
对卡 07 的回溯 → 已出库的单要改，只能倒着走本流程（全退重开）
客户信管检查点（上线后要盯的 六 点）

① 销售退回和采购退出有什么共同点？ → 都是"先入后退"：货先回到自己库里，再由后续单据冲减原来的业务（采购侧冲采购入库，销售侧冲销售出库）。

② 退回入库单之后就结束了吗？ → 是，流程到"销售退回入库单"就结束；钱上的差异另有销售冲差 / 退补处理。

③ 退回的货要不要检验？ → 要，由 QA 人员看包装有没有漏气、发潮、胀气做外观判定，并通过线下 SOP 留痕。⚠️ 按 GMP 第 137 条，退货要经"检查、检验和调查 + 质量管理部门评价"才能重新包装发运，所以外观判定之外还要留 QA 评估记录，才能满足 GMP 口径。

④ 退回的货都怎么处理？ → 看退货原因：滞销 / 包装问题 → 重新上架（包装问题可协商换包装成本）；质量问题 → 走不合格流程（登记、必要时报损销毁）。

⑤ 退货有什么必须守的规矩？ → 三条硬约束：数量 ≤ 原出货量、批号沿用原批号（重新包装的除外）、单价不能变动。

⑥ 退货对客户信用有什么影响？ → 退货会释放信贷额度——额度算法里退货单是加项（30000 − 已开票 + 回款 + 退货）。

跨年退货财务处理

✅ 退货分原因　退回有 QA 外观判定（但不走系统检验流程）　入库一般进合格品库、异常才进不合格品库　数量≤ 原出货量　批号沿用原批号（重新包装除外）　单价不变动

跨年退货怎么处理（按国家要求，企业普遍做法）：

① 会计上——若属于资产负债表日后事项（报告年度结束日至财报批准报出日之间发生），用"以前年度损益调整"调整报告年度的收入与成本。
分录：借 以前年度损益调整 / 应交税费—应交增值税（销项），贷 应收账款；同时借 库存商品，贷 以前年度损益调整。

② 税法上——一律在退货实际发生的当期冲减收入，不追溯调整原年度；会计与税法由此形成税会差异，需要做纳税调整。汇算清缴前发生与清缴后发生，处理还不一样。

③ ERP 侧要盯的口径——系统销售分析按净销售（销出 − 退货）算，跨年退货冲本年还是回冲原年会同时影响两个年度的报表。按国家要求：退货在发生当期冲减。

退回货去哪了 · 三条硬约束 + 一个分岔

接手后最容易被问到的两个点：退货单能不能随便填？货退回来放哪？
退货单本质是"倒着走的销售单"——它必须挂在当初那笔出库上，所以有三样东西不能动。
硬约束 为什么
数量 ≤ 原出货量 退货要提取原销售出库单，最多只能把当初发出去的量退回来；系统按原单卡住，防止多退。
批号沿用原批号 批号在生产完成之后就一直跟着这批货（从物料到成品到出库都是同一批），退货不改批号——退回来的就是当初发出去的那一批。
🔴 唯一例外：需要重新包装的，批号重新生成。
退回单价不得变动 退货按原出货价冲回。要调价、要退补差价，走销售冲差单这条独立线，不能借退货改价。
退货原因 QA 验收结果 去向与后续动作
滞销 / 包装问题 外观判定合格 入合格品库 → 重新上架；包装不符合客户要求的，可与客户协商换包装的成本，换好再上架。⚠️ 重新包装后批号重新生成。
质量问题 外观不合格
（漏气 / 发潮 / 胀气）		 入不合格品库 → 走不合格流程：不合格登记 → 必要时报损销毁（卡 05 / 06）；属成品复验不合格的，还要先发起商品批号停售 / 商品停售。
关键点：退回检验由 QA 走线下 SOP 完成，系统侧重记录结果。所以"进合格品库还是不合格品库"这个决定是 QA 验出来的，不是系统算出来的——这两点要注意区分。

销售冲差 / 退补 · 详解

"货没问题，是钱要调"——别跟销售退回混为一谈
销售退回解决的是货回来；销售冲差 / 退补解决的是钱对不上。两者的单据完全分开走。
类型 解决什么问题 单据链
销售退回 货要退回来 — 数量减少、库存增加 退回通知单 → 销售收货单 → WMS 拣货验收 → 退回入库单
销售冲差 / 退补 价格差、退补差价 — 数量不动，只调金额 销售冲差单申请 → 销售冲差执行
为什么要"申请 + 执行"两步：冲差直接改钱，属于敏感操作，所以要先申请、后执行——申请是"提出要调"，执行是"真正调账"，中间可以核。
08业务流程 08 · 销售退回 / 冲差流程GSP 版
业务流程 08 · 销售退回 / 冲差流程 GSP 版 模块：销售 → WMS → 仓储 · 销售的反向操作
主线流程
流程速览：跟卡 07 对着讲——销售是"货出去、钱进来"，退回是"货回来、账冲掉"。主线四步（通知单 → 收货单 → 退回验收 → 退回入库单），跟 采购退回（卡 02）同构，只是方向对着客户。跟 GMP 最大的区别：GSP 有独立的"退回验收"环节（同采购入库验收），验收不合格要进不合格登记流程；而且不存在"换包装重新上架"这一说。
1
一句话目的
把客户退回的货收回、验收、入库，同时冲减对应的销售（数量、金额），让库存和应收回到实际状态。跟采购退回（卡 02）同一个道理，只是方向对着客户而不是供应商。GSP 经营企业的核心是"退回要经过验收"——不合格的进不合格登记，合格的才回可售库存。
2
触发条件（GSP 三类场景）
由销售侧发起销售退回通知单。GSP 经营企业的退货，原因主要分三类：
① 销售开票单开错了、且已经出库——这是最典型的"改单死线"场景：开票单出库之后系统里就改不动了，只能立马做销售退回、重新开票（跟采购退回"数量错当天退"一个道理：错了就退、退了重开）。
② 产品滞销，需要退回——货本身没问题，纯粹卖不动、要退回上游。⚠️ GSP 经营企业不存在"换包装"这一说——退回的货要么重新上架继续卖，要么退上游，不会换包装改批号。
③ 特殊情况：销售出去的药品在消费者手中发现了问题——这是 GSP 质量体系里最严肃的一类，走销售退回 + 药品召回（详见第 6 问与专题卡）。
3
前置 / 上游
① 这批货已经销售出库过（上游接卡 07 销售流程的销售出库单）
② 客户已提出退货诉求（通知单的发起依据）
③ 退货要提取原销售出库单，由此带出两条硬约束：
· 退回数量 ≤ 原出货量——只能退当初发出去的那部分，不能多退
· 退回单价不能变动——退货按原价冲回，不能借退货调价（真要调价走销售冲差）
🔴 与 GMP 的差异：GMP 退货里"批号沿用原批号、重新包装才换批号"这条，在 GSP 里不涉及——经营企业退回的货不重新包装，批号始终是上游生产厂的原厂批号，退回时直接沿用原批号即可，没有"换包装重生成批号"的例外。
🔴 还有一个前提：卡 07 里已经在系统里生成了出库单据的单要改，也只能走本流程——整单全退，再重新开票，这是唯一的出路。
4
主线步骤（四步）
① 销售退回通知单（销售侧发起，记录客户要退什么、什么原因）→ ② 销售收货单（仓库收货登记，收多少、哪个批号）→ ③ 退回验收（GSP 有独立的退回验收环节，同采购入库验收）→ ④ 销售退回入库单（按验收结果入对应库，到此流程结束）。
③ 退回验收：GSP 有，GMP 没有独立环节
🔴 GSP 经营企业有独立的"退回验收"流程，和采购入库验收流程一样：判定合格 / 待处理 / 不合格三态。
· 合格 → 入合格品库，重新上架销售。
· 待处理 → 同采购入库验收的待处理流程（挂起，等质量或相关部门判定）。
· 不合格 → 🔴 进"不合格登记"流程——这是退回验收与采购验收为数不多的不同之处（采购验收不合格一般是拒收/验收退货退回上游；销售退回验收发现不合格，货已经在自己手里了，不能退回客户，只能进不合格登记、隔离、必要时报损销毁）。
④ 退回验收在 WMS 的操作
和采购入库验收的流程一模一样——手持 WMS 扫描、逐项核对、判定三态，这里不过多赘述，直接参考卡 01（采购流程·GSP）的 WMS 验收操作。
5
关键单据与字段
销售退回通知单：退货品种、数量、退货原因（决定货后续去哪）
销售收货单：实收数量、批号（沿用原厂批号，不重新包装不改批号）
退回验收：合格 / 待处理 / 不合格三态判定结果（同采购验收）
销售退回入库单：入库数量、批号、入库库房（合格→合格品库；待处理→待处理区；不合格→不合格品库并接不合格登记）、退回单价（与原出货单价一致，不得变动）
提取的原销售出库单：带回原出货的品种、数量、批号、单价——退回数量受它约束（≤ 原出货量）
支线：金额差异
销售冲差单：申请 → 销售冲差执行（处理价格差、退补差价这类"数量不动、钱要调"的情况）
6
异常与回退
按退货原因分处理（本流程最重要的一岔）
① 开票错已出库 → 整单销售退回 → 重新开票（唯一出路，货回合格品库后重新上架）。
② 滞销退回 → 验收合格 → 入合格品库重新上架继续卖；或退回上游供应商。不存在"换包装"——GSP 经营企业不做换包装改批号。⚠️ 如需退回上游，接采购退出流程（卡 02·GSP）。
③ 消费者发现质量问题 → 🔴 这是 GSP 质量体系里最严肃的一类：销售退回 + 药品召回并行处理——质量部门评估发起召回，退回的货隔离存放，进不合格登记，必要时报损销毁（详见专题卡）。
其他异常与红线
金额对不上 → 走销售冲差 / 退补（数量不动，只调金额）——注意它跟"退货"是两条并行的线，别混。
想多退 / 想改价 → 系统不允许：数量 ≤ 原出货量、单价不得变动，这两条是硬约束。
✅ 跨年退货财务怎么处理——（见卡末）：会计按"以前年度损益调整"调报告年度，税法一律在退货发生当期冲减。
7
下游衔接
退回入库 → 冲减销售 → 直接影响净销售口径（销出 − 退货），这也是销售业绩分析的口径基础
验收合格的退回品 → 回到可售库存重新上架，等于把货"变回"能卖的状态
金额影响应收 → 退货会释放已占用的信贷额度（卡 07 信贷额度算法里：发生退货单是做加法）
验收不合格的退回品 → 🔴 进不合格登记流程（隔离存放 → 登记 → 必要时报损销毁，卡 05 / 06）
滞销退上游 → 接采购退出流程（卡 02·GSP）
对卡 07 的回溯 → 已出库的单要改，只能倒着走本流程（全退重开）
客户信管检查点（上线后要盯的 六 点）

① 销售退回和采购退回有什么共同点？ → 都是"先入后退"：货先回到自己库里，再由后续单据冲减原来的业务（采购侧冲采购入库，销售侧冲销售出库）。

② GSP 退回为什么有"验收"环节？ → GSP 经营企业必须有退回验收，和采购入库验收一样判定合格/待处理/不合格三态——这是 GSP 质量文件的硬性要求。

③ 验收不合格怎么办？ → 🔴 进"不合格登记"流程——这是退回验收和采购验收最大的不同：采购验收不合格可以拒收退回上游，销售退回验收不合格货已经在自己手里，只能隔离登记、必要时报损销毁。

④ 滞销退回能换包装吗？ → 不能。GSP 经营企业不存在"换包装"这一说，退回的货要么重新上架，要么退回上游，不换包装不改批号。

⑤ 退货有什么必须守的规矩？ → 两条硬约束：数量 ≤ 原出货量、单价不能变动。（GMP 里"重新包装才换批号"这条 GSP 不涉及。）

⑥ 消费者发现问题怎么办？ → 销售退回 + 药品召回并行：质量部门评估发起召回，货隔离存放，进不合格登记、必要时报损销毁。

跨年退货财务处理

✅ 退货分原因（开票错 / 滞销 / 质量问题）　退回有独立验收环节（合格/待处理/不合格三态）　不合格进不合格登记　数量≤ 原出货量　单价不变动　不换包装

跨年退货怎么处理（按国家要求，企业普遍做法）：

① 会计上——若属于资产负债表日后事项（报告年度结束日至财报批准报出日之间发生），用"以前年度损益调整"调整报告年度的收入与成本。
分录：借 以前年度损益调整 / 应交税费—应交增值税（销项），贷 应收账款；同时借 库存商品，贷 以前年度损益调整。

② 税法上——一律在退货实际发生的当期冲减收入，不追溯调整原年度；会计与税法由此形成税会差异，需要做纳税调整。汇算清缴前发生与清缴后发生，处理还不一样。

③ ERP 侧要盯的口径——系统销售分析按净销售（销出 − 退货）算，跨年退货冲本年还是回冲原年会同时影响两个年度的报表。按国家要求：退货在发生当期冲减。

退回货去哪了 · 验收三态 + 两条硬约束

接手后最容易被问到的两个点：退货单能不能随便填？货退回来放哪？
退货单本质是"倒着走的销售单"——它必须挂在当初那笔出库上，所以有两样东西不能动。
硬约束 为什么
数量 ≤ 原出货量 退货要提取原销售出库单，最多只能把当初发出去的量退回来；系统按原单卡住，防止多退。
退回单价不得变动 退货按原出货价冲回。要调价、要退补差价，走销售冲差单这条独立线，不能借退货改价。
批号：GSP 经营企业的商品批号是上游生产厂的原厂批号，退回时直接沿用原批号，不存在"换包装重生成批号"的例外（那是 GMP 生产企业才有的事）。
退货原因 退回验收结果 去向与后续动作
开票错已出库 合格 入合格品库 → 重新上架；重新开一张正确的开票单。
滞销退回 合格 入合格品库 → 重新上架继续卖；或退回上游（接卡 02·GSP 采购退出）。不换包装。
质量问题 / 消费者发现 不合格 入不合格品库 → 进不合格登记流程（隔离存放 → 登记 → 必要时报损销毁，卡 05 / 06）；同步走药品召回。
（任一类） 待处理 同采购入库验收的待处理流程：挂起，等质量或相关部门判定后再定去向。
关键点：GSP 的"退回验收"是独立环节，判定合格/待处理/不合格三态。跟采购验收的区别只在一处：验收不合格时，采购验收可以拒收退回上游，销售退回验收只能进不合格登记——因为货已经在自己手里了。

GSP 质量文件对销售退回的补充要求

经营企业的销售退回，除了系统流程，还要满足 GSP 的质量管理要求
一句话：退货不只是"货回来"这么简单，GSP 要求每一笔退回都要有据可查、有责任可追、有隔离可管。
要求点 具体内容
退货要有审批 销售退回应由质量管理部门审核，尤其质量问题退货，需质量负责人审核签字后，仓储才能收货。
退回验收要留记录 每笔退回验收都要有验收记录（验收人、日期、数量、批号、判定结果），并建立退货台账，做到可追溯。
不合格品隔离存放 退回验收不合格的，要放在不合格品库 / 待处理区单独隔离存放，挂明显标识，不得与合格品混放，防止误发。
随货同行单 / 销售凭证 退货时核对随货同行单、销售凭证，确认是本公司售出的品种、批号，做到"货、单、票"一致。
冷链 / 特殊药品 需冷链运输的药品、特殊管理药品退回，要核查运输过程的温度记录，不符合储存条件的不得退回、不得重新销售。
消费者发现问题的召回 已售药品发现质量问题的，按药品召回制度处理：质量部门评估发起召回，召回产品登记、隔离、评价处理，并按规定上报。
落地到 ERP 的提醒：GSP 的这些质量要求，系统里能直接落的是「退货台账 / 验收记录 / 不合格品库隔离」「随货同行单核对」「退回验收三态」这几项；审批签字、冷链温度记录、召回上报更多靠纸质/线下流程 + 系统留痕配合。信管接手时，要把「系统能做到的」和「需要线下配合的」分清楚，别让客户以为系统能全自动兜底。

销售冲差 / 退补 · 详解

"货没问题，是钱要调"——别跟销售退回混为一谈
销售退回解决的是货回来；销售冲差 / 退补解决的是钱对不上。两者的单据完全分开走。
类型 解决什么问题 单据链
销售退回 货要退回来 — 数量减少、库存增加 退回通知单 → 销售收货单 → 退回验收 → 退回入库单
销售冲差 / 退补 价格差、退补差价 — 数量不动，只调金额 销售冲差单申请 → 销售冲差执行
为什么要"申请 + 执行"两步：冲差直接改钱，属于敏感操作，所以要先申请、后执行——申请是"提出要调"，执行是"真正调账"，中间可以核。

09业务流程 09 · 财务流程：销售收款（应收）
业务流程 09 · 财务流程：销售收款（应收） 模块：销售 → 财务 · 与卡 04 采购付款正好对称（一个收钱，一个付钱）
主线流程
流程速览：跟卡 04 对着讲——采购付款是"钱出去、把应付平掉"，销售收款是"钱进来、把应收平掉"。三个管：发票管"该收多少"、核销管"这笔钱对哪张单"、收款计划管"什么时候收"。
1
一句话目的
把该收客户的钱算清楚、开票、收回来、对上账，最终应收账款结清。它是销售流程的"收尾"：前面的销售订单、开票单、出库单解决"货怎么出去"，这一步解决"钱怎么回来"。
2
触发条件
销售出库之后——结算时点在出库之后，出库了才有开票的依据。
开票分两种情况：
① 接入了财务接口 → 系统自动生成发票（部分企业对接的是税务开票接口，直接与税务局连接）；
② 没接入财务接口 → 需要财务人员去税务局开具（手工开票后回系统登记）。
⚠️ 这里要分清两个"开票"：销售开票单是 ERP 里的发货业务凭证（在出库之前就开了，卡 07 讲过）；这一步说的"开票"是税务发票（出库之后才开）。名字都叫开票，不是一回事。
3
前置 / 上游
① 销售出库单已生成（上游接卡 07 销售流程；出库这一步同时也是"改单的死线"）
② 客户资料已维护：付款方式、收款方式、开户银行、发票类型、信贷额度
③ 是否接入财务接口已确定（决定发票是自动生成还是人工去开）
④ 客户往来账历史清晰（有余额才能谈核销、才能走预收款）
4
主线步骤（四步）
① 销售出库（卡 07 的终点，也是本卡的起点）→ ② 开票（接入财务接口→自动生成发票 / 没接入→财务去税务局开）→ ③ 形成应收账款（收款方式 = 应收账款时进应收）→ ④ 收款 + 核销（勾兑） → 应收结清。
收款计划（管控层）
跟采购侧的付款计划是同一个位置——规划"什么时候收、收多少"，属于管控层；也可以跳过计划直接按单据核销（那就是财务单方收款，业务部门不参与）。
5
关键单据与字段
销售开票单抬头 · 收款方式：应收账款 / 现金——这是销售侧"钱走哪条路"的总开关，后续的出库单、收款计划都会体现这个选择
税务发票：发票类型、发票号码、发票日期、金额、税额（价税分离）
应收账款：应收金额、已收金额、未收金额、账期
收款单 / 收款计划：收款金额、收款方式、收款日期、勾兑（核销）对象
预收款相关：预收款申请 → 预收款确认单（客户先付钱）
预付款相关：预付款申请 → 预付款确认单（企业先付给供应商，属采购侧，同一套机制）
6
异常与回退
开票单改了（还没出库）
开票后改单价 / 改数量（此时还没出库）→ 系统自动触发预警提醒，但不需要审批——预警是"喊一声让相关人知道"，不是"卡住不让改"。
现金业务
开票单抬头收款方式选"现金" → 后面的出库单、收款计划等都会体现；现金业务的特点是钱货两清、不进应收，所以重点是盯"现金未结款"（货发了、钱没到）。
开错了
发票开错 → 冲红（作废重开或开红字发票）；
收款收错 / 核销核错 → 冲销后重新核销（跟采购侧同一套逻辑）。
7
下游衔接
应收核销 → 总账凭证（销项税额、收入确认）
与客户往来对账：往来账页余额随核销减少；退货也挂在这条线上（卡 08 的退货会释放信贷额度、冲减应收）
净销售口径：销出 − 退货，是销售业绩分析的口径基础
利润在这里算出来：销售收入 − 销售成本，销售成本见下方专题卡（GMP 生产企业要算料工费，GSP 经营企业只算购进成本）
资金计划：收款计划的数据反哺资金计划（跟采购侧的付款计划镜像）
客户信管检查点（上线后要盯的 六 点）

① 销售收款和采购付款有什么关系？ → 同一套逻辑的镜像：采购侧是"钱出去、平应付"，销售侧是"钱进来、平应收"；核销（勾兑）的做法、计划的位置、冲错的处理，两边一模一样。

② "开票"有几个意思？ → 两个：销售开票单（ERP 业务凭证，出库前）和税务发票（出库后，接接口自动生成或去税务局开）。要分清是哪一个。

③ 什么时候结算？ → 销售出库之后。出库是"货走了"，开票是"钱该收了"，两件事一前一后。

④ 收款方式选"应收账款"和选"现金"有什么区别？ → 应收账款进应收、走账期和信贷额度；现金不进应收，钱货两清，重点是盯现金未结款。

⑤ 开票后改单价 / 数量会不会被卡住？ → 不会（前提是还没出库）。系统自动预警提醒，但不审批。

⑥ 销售成本包含哪些？ → 分两种企业看：GMP 生产企业的销售成本 = 采购成本 + 人工成本 + 物料成本（还要算生产损耗），因为它要生产；GSP 经营企业的销售成本 = 购进成本，因为它只"买进卖出"、不做加工，不需要归集人工和物料。收入和成本一减，利润就出来了。

补充说明

① 财务接口 = 税务开票接口（直接与税务局连接）——接入后发票自动生成。

② 收款计划要审批：销售经理审批（对称地，采购付款计划是采购经理审批）。

③ 现金未结款预警的触发条件 = 按销售账期：每个客户有单独的账期天数，超过该客户账期天数未收款即预警。

④ 客户退款：按国家规定的财务流程开发票（红字）后退给客户；在系统里体现为销售收款勾兑结算。

销售成本 → 利润 · 是怎么算出来的

销售不是"卖出去就完事"，要算清这一单到底赚不赚钱
一句话：利润 = 销售收入 − 销售成本。销售收入好懂（卖了多少钱），难的是销售成本——而销售成本怎么算，GMP 生产企业和 GSP 经营企业完全不同。
GMP 生产企业 · 销售成本 = 料 + 工 + 费
成本构成 是什么 注意点
① 采购成本 买中药材、辅料、包材花的钱 药材价格波动大，是成本的大头
② 人工成本 生产过程中各道工序的人工费用（净制、切制、炮炙、包装…） 炮制工序越多，人工摊得越多
③ 物料成本 实际投进去的物料价值 🔴 要把生产过程中的损耗算进来——投 100 斤出 85 斤，损耗那 15 斤也是成本
为什么生产企业要算这么细：生产企业把原材料加工成成品，中间的人工（各道工序）和物料损耗都是真实发生的成本，不归集进去，利润就是虚的。
GSP 经营企业 · 销售成本 = 购进成本
成本构成 是什么 注意点
购进成本 买进来这批商品花的钱（进价 + 相关费用） 商品不做加工、直接转卖，成本就是"进货的钱"
为什么经营企业不用算料工费：GSP 经营企业是买进卖出，不经过生产加工环节，没有人工工序、没有物料损耗，所以销售成本就是购进成本（进价加采购相关费用），直接按 库存商品 → 主营业务成本 结转即可。
系统里的通用落点：系统有商品定价功能，成本、定价、利润都在这块体现——先有成本（GMP 是核算出的生产成本 / GSP 是购进入库成本），才有底价；定价定了，卖出去才知道赚多少。
销售分析看的是 净销售（销出 − 退货），而利润分析看的是 净销售 − 销售成本——两个口径别混。

预收款 / 预付款 · 申请 + 确认单

先收钱后发货、先付钱后收货，这两种"提前"怎么走系统
两边是对称的一对：销售侧"客户先给钱"= 预收款；采购侧"我们先给供应商钱"= 预付款。各自都是两步走：申请 → 确认单。
类型 单据链 对往来账余额的影响
预收款
（客户先付）		 预收款申请 → 预收款确认单 🔴 客户往来账余额减少。客户提前把钱付了，等于应收被提前冲掉一块：借 银行存款 / 贷 应收账款（预收账款）——收钱的动作，余额往下走
预付款
（我们先付）		 预付款申请 → 预付款确认单 🔴 供货商往来账余额减少。我们提前付了钱，等于应付被提前冲掉一块：借 应付账款（预付账款）/ 贷 银行存款——付钱的动作，余额往下走
一句话记法：确认单一确认，就往"已经结掉一部分"的方向走——预收款让客户欠我们的钱变少，预付款让我们欠供应商的钱变少。两边都是余额减少，方向一致、主体相反。
⚠️ 余额在往来账页里怎么显示（是显示净余额，还是把预收/预付单列），要在系统里实际看一眼——会计原理是这样，具体界面表现以系统为准。

现金业务 vs 应收账款 · 开票单抬头那个开关

销售开票单抬头「收款方式」一选，后面整条链就分了岔
收款方式 走哪条路 要盯什么
应收账款 形成应收 → 按账期回款 → 核销；占信贷额度 账期是否逾期、信贷额度是否超限（卡 07 的两道校验）
现金 钱货两清，不进应收；出库单、收款计划都会体现这个选择 🔴 现金未结款——按销售账期预警（每客户单独账期天数，超天数未收款就预警到开票员）
为什么现金业务反而要盯：应收有账期、有额度、有校验，系统天然会拦；现金业务是"当场结清"的预期，一旦货发出去了钱没进，就成了没有应收账期保护的裸风险——所以现金未结款必须单独预警。预警口径 = 按每个客户自己的账期天数，超出即预警（不是统一固定天数）。
10业务流程 10 · WMS 仓储作业流程（手持 + 电脑端）
业务流程 10 · WMS 仓储作业流程 模块：仓储（WMS）· 手持 PDA + 电脑端 · 横跨采购与销售
主线流程 · 手持 + 电脑端
流程速览：这张卡是采购和销售中间的"手脚"——采购的货怎么上架、销售的货怎么拣出来，都在这里。分两块讲：手持设备（现场干活的）和电脑端 WMS（管标签、管规则）。
1
一句话目的
让仓库里的每一个动作都留痕、账实一致：货在哪一货位找得到、每一批货的来龙去脉追得到、库存数字和实物对得上。它不产生库存，但它是库存准不准的关键。
2
触发条件
两类单据下发仓库就触发作业：
① 采购收货单下发仓库 → 触发上架作业（并自动打印上架标签）
② 销售开票单下发仓库 → 触发拣货作业（并自动打印拣货标签）
另外：仓库自己发起的盘点、移库也走 WMS。
3
前置 / 上游
① 货位已维护（整货位 / 散件货位；中药饮片常是整散合一的货位）
② 货位标签已打印粘贴——手持设备靠扫标签认货位
③ WMS 与 ERP 已对接（单据能从 ERP 下发到 WMS，作业结果能回写）
④ 作业人员有对应权限（上架 / 拣货 / 复核 / 盘点）
4
主线步骤（手持设备上的活儿）
① 采购上架：收货后扫上架标签 / 货位标签，把货放到指定货位
② 销售拣货：按先进先出（FIFO）拣货，系统按批号自动推荐该拣哪个批号
③ 复核：拣完有复核人二次确认——拣货和发货可以是同一个人（中药饮片公司常有"单独库房只有一个负责人"的情况），但复核这道确认要有
④ 盘点：在手持上做（盘库、录实盘数）
⑤ 移库 / 拣货移库：拣货时发现散货货位库存不足 → 系统自动触发移库拣货流程，从整货位给散货货位补库存（GSP 认证公司的 WMS 也是这样）。中药饮片是整散合一的货位，逻辑同上
⑥ 销售退货验收：退回的货在手持上验收（详见卡 08）
⑦ 采购退回复核：采购退出时复核出库
5
关键单据与字段（电脑端 WMS 管什么）
货位标签打印（电脑端 WMS 软件）：打印货位条码，贴到货架上，手持扫码认位
自动打印拣货标签：销售开票单下发给仓库之后，系统自动打印出对应品种、批号的货位——拣货员拿着标签知道去哪个货位拣
自动打印上架标签：采购收货单下发给仓库之后，系统自动打印出对应品种的货位；
⚠️ 批号为空也能下发/打印：空的货位（该货位上当前没有任何品种的批号库存）可以；曾经存过其他品种的批号库存、但此时库存为空的货位也可以
货位 / 批号 / 数量：WMS 作业的三要素（扫货位、扫批号、录数量）
6
异常与回退
拣货时散货货位不够 → 系统自动触发移库拣货流程：从整货位补到散货货位，再继续拣
盘点有差异 → 走盘点确认单：盘盈（有多）→ 走损溢开票单，库存增加、库存金额增加；盘亏（有少）→ 库存减少、库存金额减少
退回货验收不合格 → 入不合格品库，走不合格流程（卡 05 / 06 / 08）
标签打不出来 / 扫不出 → 先补打标签、确认货位维护无误，否则作业无法继续
7
下游衔接
作业完成 → 回写 ERP → 库存数量准确，这是后面所有环节的地基：
· 销售能开票（有库存）→ 卡 07
· 采购能入库（账实一致）→ 卡 01
· 复验能按批号发起（批号库存清楚）→ 卡 06
· 损溢、退货能对上数（发没发、退没退）→ 卡 08
先进先出执行得好 → 老批号不压库 → 效期风险小（这也是卡 07 里 FIFO 提醒的落点）
客户信管检查点（上线后要盯的 六 点）

① 拣货和发货是不是必须两个人？ → 不是。中药饮片公司常有单独库房只有一个负责人的情况，拣货和发货可以是同一人；但拣货有复核人二次确认，这道确认不能省。

② 拣货按什么顺序？ → 先进先出（FIFO），系统按批号自动推荐；不过销售开票单阶段已经执行过一次 FIFO 标准了，WMS 这一步是执行落地。

③ WMS 认不认 AngleId（批次维度）？ → 常见的 GSP 认证 WMS 不受 AngleId 影响（它只认批号）。⚠️ 但不是所有 WMS 都这样——具体要看客户用的是哪套 WMS。

④ 销售退货验收、采购退回复核这两个功能，GMP 企业一定有吗？ → 不一定。这两个功能在GSP 认证企业的手持 WMS 上常见；GMP 法规对软件功能没有强制规定，它管的是"要有规程、有记录、有质量评价"（详见下方专题卡）。

⑤ 上架标签批号为空为什么也能下发？ → 因为标签打的是货位、不是批号。空货位（或曾存过其他品种、现在已空的货位）照样能放货，所以标签照样能打。

⑥ WMS 做完作业，ERP 里库存什么时候变？ → 作业结果回写 ERP 后库存才动；这也是为什么要账实一致——WMS 不准，ERP 就不准。

补充说明

① WMS 厂商 = 行业主流 WMS 服务商（本卡的平台选型细节由客户信管负责，实施侧不再展开）。

② 整散合一货位下的拣货移库：散货货位不足时，系统自动触发移库拣货流程（GSP 认证公司的 WMS 也是这样）。

③ 盘点差异：走盘点确认单——盘盈（有多）→ 走损溢开票单，库存增加、库存金额增加；盘亏（有少）→ 库存减少、库存金额减少。

GMP vs GSP · 仓储和退货验收到底谁管

两个关键问题：GMP 企业要不要"销售退货验收 / 采购退回复核"？中药饮片退货检不检？
先把两个法规的角色分清楚：GMP = 生产（药品生产质量管理规范，管生产企业）；GSP = 流通（药品经营质量管理规范，管经营/流通企业）。
问题 答案 依据 / 说明
手持 WMS 要有"销售退货验收"吗？ GMP 不强制 GMP 是管理规范，规定的是"要有操作规程、要有记录、要有质量评价"，不规定用什么工具（纸质、电脑、手持都行）。GSP 企业的手持 WMS 常见这两个功能，那是软件厂商按流通业态设计的。生产企业要不要看企业选型。
手持 WMS 要有"采购退回复核"吗？ GMP 不强制 同上。生产企业"采购退出"的复核走的是单据审批 + 质量确认（卡 02），不一定非要手持扫码复核。
退回的中药饮片要不要检验？ 要，而且不只是外观 🔴 GMP（2010修订）第137条：只有经检查、检验和调查，有证据证明退货质量未受影响，且经质量管理部门评价后，方可考虑重新包装、重新发运销售。所以系统里只有"外观判定"是不完整的——至少要有 QA 的评价记录，必要时取样检验。
GMP 第一百三十六条（退货记录）：企业应当建立药品退货的操作规程，记录至少包括 产品名称、批号、规格、数量、退货单位及地址、退货原因及日期、最终处理意见；同一产品同一批号不同渠道的退货应当分别记录、存放和处理。
GMP 指南（第2版）第539页 10.5 退货的处理决定——按风险分三种：
① 无法追溯全部历史信息、内包装破坏 → 销毁；
② 原始大箱状态良好、历史信息清晰、剩余有效期可接受 → 可考虑重新包装、重新放行发运销售；
③ 包装良好、温控记录全面，但不确定有无其他负面因素 → 应取样检验 + 历史稳定性数据综合评估，合格后方可重新包装放行。

三个标签 · 什么时候打、打的是什么

货位标签（人工/批量）、拣货标签（自动）、上架标签（自动）
标签 什么时候打 打出来的是什么
货位标签 货位维护好之后（电脑端 WMS） 货位条码，贴在货架上——手持设备靠它认"这是哪个货位"
拣货标签（自动） 销售开票单下发给仓库之后 对应品种 + 批号的货位——拣货员拿着去拣
上架标签（自动） 采购收货单下发给仓库之后 对应品种的货位——上架员拿着去放。⚠️ 批号为空也能打：空货位、或曾存过其他品种但现在已空的货位，都可以
为什么拣货标签带批号、上架标签不带：拣货是"从已有的库存里挑出指定批号"，所以必须精确到批号；上架是"给新到的货找个位置放"，位置（货位）定了就行，批号是这次上架才落位的。

电子标签拣货系统 · 退货拣货的硬件联动

GSP 经营企业特有、GMP 生产企业没有的一环——退货拣货时，标签 + 扫描枪 + 蜂鸣器 + 货位灯一起联动
一句话：退货拣货任务下发 → WMS 绑定打印拣货标签（含货位信息）→ 扫描枪扫标签拣货 → 蜂鸣器 + 总控制器 + 亮灯标签三重提示 → 拣完拍灭标签。
1
四步怎么走
第一步 · 任务下发：退货拣货任务下发后，WMS 绑定打印拣货标签（标签里含货位信息）
第二步 · 扫描：用标签打印的扫描枪直接扫描拣货标签
第三步 · 三重提示：① 货位上的蜂鸣器亮起（一个库区一个，如中成药拣货任务 → 中成药库区蜂鸣器响 + 亮）；② 每排货位的总控制器显示出对应货位；③ 对应的标签亮起并显示拣货数量
第四步 · 拣完拍灭：拣完货后，直接拍灭对应的标签按钮（这套"亮灯 → 拍灭"的现场操作，理解成"灯亮提示该货位有活、拍灭表示干完了"）
什么时候用这套：主要用在采购退货复核（卡 02）和销售退回验收（卡 08）的拣货环节——GSP 经营企业退货要走"复核出库"，靠这套标签硬件把"哪个货位、拣多少"提示到现场，避免拣错。
跟"三个标签"的关系：上一条讲的货位标签 / 拣货标签 / 上架标签是"打标签、认货位"；本条的电子标签拣货系统是更进一步——标签不只是"认位"，还和蜂鸣器、总控制器、亮灯联动，构成一套拣货提示硬件。都是 GSP 经营企业 WMS 的标配，GMP 生产企业不一定上这套。

仓储硬指标 · GMP 与 GSP 检查各看这些

来源要分清：GMP 附录·中药饮片（2014年第32号公告）管"分库存放、留样、复验"；垛间距、湿度区间、色标管理这些具体数值是 GSP（药品经营质量管理规范）第83条对经营企业仓库的要求
出处 项目 要求
GMP 附录 分库存放 中药材与中药饮片应分库存放；毒性中药材和饮片专库存放，并有防盗及监控设施（附录第24条）
GMP 附录 温湿度监控 仓库应配备设施并对温、湿度进行监控，保证按规定条件贮存；附录未给统一数值，按品种标准执行；易串味、鲜活药材要有专库/冷藏（附录第25条）
GMP 附录 养护 / 复验 按规定条件贮存养护，养护操作要有养护记录；制定复验期并按期复验（附录第35、36条，对应卡 06）
GMP 附录 留样 每批中药材和中药饮片应当留样；中药饮片留样量至少为两倍检验量，留样时间至少为放行后一年（附录第53条，对应卡 01 留样单）
GSP 第83条 相对湿度 储存药品相对湿度为 35%—75%（是区间，不是只设上限）
GSP 第83条 垛位间距 垛间距≥5cm；与库房内墙、顶、温控设备及管道≥30cm；与地面≥10cm（离地存放）
GSP 第83条 色标管理 按质量状态实行色标管理：合格药品为绿色、不合格药品为红色、待确定药品为黄色
📌 一句话：GMP（生产）管"分库存放 + 留样 + 复验"这类生产仓储要求；垛间距、湿度 35%-75%、色标管理这些具体数值是 GSP（经营）第83条的仓库要求。两者别混——面试被问到出处时，说错了反而减分。
11业务流程 11 · 商品养护流程
业务流程 11 · 商品养护流程 模块：仓储 → 质量 · 停售的另一触发源 · 养护周期驱动
主线流程 · 养护 + 不合格处置
流程速览：先立住养护是"储存期间保质量"的日常动作，再讲周期怎么定、日期怎么算、怎么预警，最后落到养护发现问题怎么处置（这是它跟卡 06 复验并联的"停售触发源"）。
1
一句话目的
通过科学管理手段，确保药品在储存期间质量稳定、安全有效——具体是：维持药效、避免失效变质、降低用药风险，并满足法规要求（GMP/GSP 对在库药品养护的硬性要求）。
2
触发条件
达到预计养护日期就触发养护——预计养护日期不是人手工填的，是按入库日期 + 养护周期自动算出来的：
① 入库日期：采购入库日期 或 生产成品入库日期
② 养护周期：来自商品详细资料里的「养护周期」字段（重点养护 = 30 天、普通养护 = 90 天）
③ 到期预警：系统自动预警到仓储部门——重点养护满 20 天（自入库日起算，或距上次养护日期起算）、普通养护满 80 天时提醒。
3
前置 / 上游
① 商品详细资料已维护「养护周期」（30 / 90 天，这是养护的源头参数）
② 药品已入库（采购入库 或 生产成品入库，才有入库日期可加周期）
③ 重点养护品种已提前确认（在 ERP 里勾选，不考虑批号——只要这个品种是重点，所有批号都按重点养护走）
④ 货位已维护（养护时按 WMS 货位定位，如 中药饮片货位 01-01-02）
4
主线步骤
① 定周期：商品资料里维护养护周期（重点 30 天 / 普通 90 天）
② 算日期：系统按「入库日期 + 养护周期」自动生成预计养护日期（注意是按库房养护，如一般药材常温库、一般药材阴凉库）
③ 预警：到期前（满 20 天预警 / 满 80 天预警）自动预警到仓储部门
④ 做养护：分两条路——ERP 系统登记养护记录（一般情况）或 WMS 手持做养护记录（特殊情况）
⑤ 登记完成：把当前日期存为「养护日期」，本次养护留痕
第一次养护的时间窗口
在养护周期内（当前日期 < 入库日期 + 养护周期 − 20 天）就可以做养护（此公式是 GSP 认证公司的养护情况举例，实际以系统配置为准）。
5
关键单据与字段
养护周期（商品详细资料字段）：30 天 = 重点养护、90 天 = 普通养护
预计养护日期：入库日期 + 养护周期（系统自动生成，非人工填）
养护日期：登记养护记录完成时，存当前日期
重点养护品种：在 ERP 里单独确认（不考虑批号，按品种维度）→ 养护时"提取重点养护品种"单独维护，不与普通品种混——有效规避养护周期 / 养护日期混淆
WMS 货位：养护时显示货位（如 01-01-02），定位链条是商品 → 商品批号 → WMS 货位
6
异常与回退（近效期 + 养护发现不合格）
🔴 近效期处置（GSP 经营企业特有）
近效期 3 个月以内 → 直接停售：商品临近有效期（3 个月以内），直接走停售——不是"提醒一下"，是硬性停售，效期内卖不掉就等报损销毁。
没到近效期 → 正常养护：距离效期还有一段时间，就按正常养护节奏走（周期 + 预警），养护中发现问题了，再走不合格流程。
养护发现不合格的两条处置路径
养护过程中发现无论怎么养护都不合格的药品：
第一步永远是先做「商品批号停售」——如果该品种全军覆没、都不合格，走商品停售流程（停售是卡 06/07 讲的同一套机制）
两条处置路径
① 可退货（原料/辅料/包材 · 入库不足 30 天）：第一次养护时刚入库不到 30 天 → 可与供货商协商走退货流程
② 只能报损销毁（超过退货窗口）：超过这个日期天数 → 走完整链条：批号停售 → 不合格品登记 → 损溢开票单 → 损溢执行单 → 不合格药品销毁
7
下游衔接
养护正常完成 → 更新养护日期，进入下一个养护周期循环
养护发现不合格 → 接停售（卡 06 复验、卡 07 销售里的停售机制）→ 不合格登记 / 损溢 / 销毁（卡 05 / 06）
与复验的关系：复验（卡 06）和养护（本卡）是"停售"的两大触发源——复验是到期主动复检，养护是储存期间持续保质量；两者发现不合格都先停售。
客户信管检查点（上线后要盯的 七 点）

① 养护周期在哪维护？ → 商品详细资料里的「养护周期」字段——30 天是重点养护、90 天是普通养护，这是养护的源头参数，客户建商品资料时就要定对。

② 预计养护日期是谁算的？ → 系统自动算：入库日期（采购/生产入库）+ 养护周期。不是人工填的，所以入库日期准、周期准，日期才准。

③ 到期怎么提醒？ → 自动预警到仓储部门：重点养护满 20 天、普通养护满 80 天（自入库日起算，或距上次养护日期起算）时提醒。

④ ERP 养护和 WMS 手持养护能同时用吗？ → 不能，二选一。一般情况在 ERP 登记养护记录，特殊情况（如需要现场扫码）用 WMS 手持做；别混在一起，数据会乱。手持养护完成后会生成养护日期 + 预计养护日期传回 ERP，可查对应记录。

⑤ 重点养护品种怎么跟普通品种分开？ → 先提前在 ERP 里确认重点养护品种（不考虑批号，按品种维度），然后在"药品在库养护"里"提取重点养护品种"单独维护——这样重点和普通的养护周期、养护日期不会混。

⑥ 近效期怎么办？ → 近效期 3 个月以内直接停售（硬性停售，不是提醒）；没到近效期就正常养护，养护中发现问题再走不合格流程。

⑦ 养护发现不合格怎么处理？ → 先做商品批号停售（全品种不合格走商品停售）；原料/辅料/包材入库不足 30 天可跟供货商协商退货；超过则走「批号停售 → 不合格登记 → 损溢开票单 → 损溢执行单 → 销毁」。

养护规则要点

养护周期 30/90 天、预警阈值 20/80 天、重点品种按品种不按批号确认、ERP 与 WMS 手持二选一、不合格先停售再分退货/销毁两条路，均已落卡。⚠️ 预警时点（重点满 20 天、普通满 80 天）是常见配置举例，实际天数以客户系统配置为准。

养护周期 30 vs 90 天 · 详解

重点养护和普通养护的差异，是这张卡的"根"
类型 养护周期 到期预警 说明
重点养护 30 天 满 20 天预警 重点品种需提前在 ERP 确认（不考虑批号，按品种维度）；养护时"提取重点养护品种"单独维护
普通养护 90 天 满 80 天预警 默认养护节奏；与重点品种分开维护，避免周期/日期混淆
为什么重点养护要单独确认：重点品种养护更频繁（30 天一次）、风险更高，如果跟普通品种（90 天一次）混在一张表里，养护周期和养护日期就会串。提前确认 + 单独提取，是让系统把两类自动分开管理。

ERP 养护 vs WMS 手持养护 · 详解

两条路都能做养护，但只能选一条
方式 适用场景 特点
ERP 系统登记 一般情况 直接在 ERP「药品在库养护」里登记养护记录，显示 WMS 货位（如 01-01-02）
WMS 手持养护 特殊情况（需现场扫码） 手持上做养护，也会生成养护日期 + 预计养护日期，完成后传回 ERP可查记录；重点品种同样要在 ERP 先确认
🔴 关键约束：二选一，别混用——同一批货要么走 ERP 养护、要么走 WMS 手持养护，混着做数据会乱（两边的养护日期、记录对不上）。上线时就要定好"哪类货走哪条路"的规则。

近效期停售 · GSP 经营企业的效期管理

经营企业买的商品都带有效期，"近效期"是它特有的停售触发源
一句话：近效期 3 个月以内 → 直接停售；没到近效期 → 正常养护，发现问题再走不合格。
效期状态 系统动作 后续去向
近效期 3 个月以内 🔴 直接停售（硬性停售，不是预警提醒） 效期内卖不掉 → 等报损销毁（接不合格 / 损溢流程）
还没到近效期 正常养护（按养护周期 + 到期预警走） 养护中发现问题 → 走不合格流程（先停售 → 不合格登记 → 报损）
跟 GMP 生产企业的区别：GMP 生产企业的"停售触发源"主要靠在库复验（卡 06，时间到了重新检）；GSP 经营企业除了养护发现不合格，还多了"近效期"这一条——因为经营企业买进的商品都带上游定的有效期，临近效期卖不掉就是损失，所以要在效期前主动停售、及时催销或报损，不能等过期了才处理。
停售的完整口径：停售一共三个触发源——复验不合格（卡 06）、养护发现不合格（本卡）、近效期（本卡）。三个都落到同一个"停售"动作上，先停售后处置。
