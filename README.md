## 一、这是什么

一句话：**把医药 ERP 实施中「人会问、会踩坑、会挨审计」的地方，写成一张张能独立看懂、也能串起来的卡。**

它解决三个具体问题：

1. **业务说不清** —— 客户一线讲流程容易"跳步"，只讲正常路径，不讲异常。这里把正常路径与异常路径都写在纸面上。
2. **合规说不准** —— GMP 与 GSP 的要求经常被混讲。这里**强制分线**：哪些条款管生产、哪些管经营，各自出处在哪，一目了然。
3. **交付说不透** —— 上线后真正扯皮的是"这笔单子为什么改不了""这批货为什么退不掉"。这里把系统的**硬约束**（死线）单独拎出来标红。

适用对象：

- 医药 ERP / WMS **实施顾问**、**项目经理** —— 需求调研、方案讲解、上线答辩的业务底稿
- **客户信息管理员 / 关键用户** —— 接手维护时的工作手册
- **行业新人** —— 医药业务流程入门的结构化材料

## 二、覆盖哪些流程（11 大流程 / 14 个章节）

按文档出现顺序排列。**编号 = 章内锚点，"GMP 版 / GSP 版" 表示该流程因认证体系不同而拆成两个独立章节。**

| # | 流程 | 版本 | 一句话说明 | 对应模块 |
|---|------|------|-----------|---------|
| **01** | 采购流程 | **GMP 版** | 来料（原料 / 辅料 / 包材）：初验 → 收货 → 请验 → 取样检验 → **放行** → 入库 | 采购 → 质检 → 仓储 |
| **01** | 采购流程 | **GSP 版** | 来货（药品 / 中药材 / 非药品）：采购订单 → 收货 → **验收** → 上架，不走"放行" | 采购 → 质管 → 仓储 / WMS |
| **02** | 采购退出流程 | **GMP 版** | 采购退货：先入库（物理隔离）→ 走退出开票 → 出库冲减库存 | 仓储 → 采购 → 财务 |
| **02** | 采购退出流程 | **GSP 版** | 采购退货：验收不合格直接退 / 滞销退 / 数量错当天退 | 仓储 → 采购 → 财务 |
| **03** | 生产流程 | 通用 | **两段式**：中间品炮制（投料=原药材）→ 成品包装（投料=中间品），各审一次指令 | 生产 → 质检 → 仓储 |
| **04** | 财务 · 采购付款（应付） | 通用 | 采购入库后开票 → 与应付账款**勾兑** → 付款计划 → 付款 | 财务 |
| **05** | 物料检验不合格处理与复检 | 通用 | **一进三出**：返工复检 / 退货 / 报损销毁，三条出口 | 质检 → 仓储 / 采购 / 财务 |
| **06** | 质量复验流程 | 通用 | 在库超期复检：**一进两出** —— 合格继续卖 / 不合格**报损**（不是退货） | 质检 → 仓储 → 财务 |
| **07** | 销售流程 | **GMP 版** | 销售开票单 → **四道自动校验**（含 FIFO 先进先出）→ 出库 → 签收 | 销售 → 仓储 → WMS |
| **07** | 销售流程 | **GSP 版** | 销售开票单 → **三道自动校验**（GSP 无 FIFO）→ 出库 → 签收 | 销售 → 仓储 → WMS |
| **08** | 销售退回 / 冲差流程 | **GMP 版** | 客户退货收回入库 + 冲减销售；**先入后退** | 销售 → 仓储 → 财务 |
| **08** | 销售退回 / 冲差流程 | **GSP 版** | 退货分三类：开票错已出库 / 滞销 / **消费者发现质量问题（走召回）** | 销售 → 质管 → 仓储 |
| **09** | 财务 · 销售收款（应收） | 通用 | 销售出库后开票 → 应收勾兑 → 收款单 → 核销 | 财务 |
| **10** | WMS 仓储作业流程 | 通用 | 手持端 + 电脑端分工：收货上架 / 拣货 / 复核 / 退货验收 | 仓储 / WMS |
| **11** | 商品养护流程 | 通用 | **养护周期 30 / 90 天**、近效期停售、养护发现不合格 → 报损 | 质管 → 仓储 |

> **补充**：除 11 张主流程卡外，文档还内嵌了 **39 张专题详解卡**（留样单、批号逻辑、一品多价、三种勾兑方式、退回货去哪了 等），详见 [第七节](#七专题卡清单速查)。

## 三、为什么这么写（编写方法）

### 1. 以「问题」而非「功能菜单」组织

传统实施文档的写法是"点开 XX 菜单 → 填 XX 字段"，看完了还是不知道**为什么**。
这里每张卡的主干都是一条线索：**谁触发 → 走哪些单 → 卡在哪 → 错了怎么办**。菜单只是路径，业务逻辑才是内容。

### 2. 强制 GMP / GSP 分线，不做"通用流程"

医药行业最大的认知陷阱：**同一个"采购"，生产型企业和经营型企业完全是两套逻辑。**

- 生产型（GMP）：核心动作是 **放行**（QP 终判），货物先进来再决定能不能用
- 经营型（GSP）：核心动作是 **验收**，三态判定（合格 / 待处理 / 不合格）直接决定货位

所以 01 / 02 / 07 / 08 四个流程**各自拆成两章**，不合并、不折中。03～06、09～11 骨架相通，才写成通用卡，但卡内会按需点出差异。

### 3. 把「死线」标成红字

系统里最要命的不是正常流程，而是**做错了就退不回去的操作**。文档中用 🔴 单独标记这类硬约束，例如：

- 销售开票单**已经出库**后，没有"改单"这个选项 —— 只能整单走销售退回，再重新开票，**没有第二条路**
- 复验不合格**不是退货，是报损** —— 货是自己的，损失自己承担
- 采购退出与销售退回都遵循 **"先入后退"** —— 货先回库，再由后续单据冲减原业务

### 4. 每张卡都收口到「上线后要盯什么」

流程讲得再漂亮，落地靠的是检查点。每张卡的结尾都有一组 **客户信管检查点**（3～7 条），写的都是上线后最容易出问题的地方，比如：

- 为什么不合格也要审批过去？（权限分层：QA 主管核完成度、质量负责人掌否决权）
- 留样留多少？（至少够全检重做一遍的量 / 放行后一年）
- 滞销退回的货去哪？（入合格品库重新上架，**不存在"换包装"**）

## 四、每张卡的结构（七段式）

所有主流程卡都遵循同一套骨架，方便跨流程对比检索：

| 段落 | 回答什么问题 | 关键内容 |
|------|------------|---------|
| **① 一句话目的** | 这个流程到底解决什么 | 一段话说清业务目标 |
| **② 触发条件** | 什么情况下启动 | 正常触发 + 特殊场景（如 GSP 退货分三类） |
| **③ 前置 / 上游** | 从哪个流程接过来 | 上游单据、必须已前置的状态 |
| **④ 主线步骤** | 具体怎么走 | 分步 + **流程可视化图（SVG）** |
| **⑤ 关键单据与字段** | 涉及哪些单、表什么信息 | 单据名 + 必填字段 + 字段含义 |
| **⑥ 异常与回退** | 出错了怎么办 | 岔路、死线、退不掉的情况 |
| **⑦ 下游衔接** | 走到哪儿交棒 | 下一个流程、下一张卡 |

配套还会出现这些区块：

- **流程速览（note）** —— 主干一句话串起来
- **关键结论（confirm / done）** —— 该卡最重要的事实收口，适合快速复盘
- **专题详解卡** —— 某一单据 / 概念的深挖（如「留样单 · 详解」「三种勾兑方式 · 详解」）

## 五、主线流程框架（图）

医药 ERP 的业务主干可以归纳为 **三条线 + 两个支点**：

```
                    ┌───────────────── 采购线（进）─────────────────┐
                    │                                               │
  【01 采购】──→ 质检/放行 ──→ 入库 ──→ 【04 采购付款】──→ 应付核销
        │                          │
        │ 不合格                   │ 超期
        ↓                          ↓
  【05 不合格处理】          【06 质量复验】
   返工/退货/报损             合格继续卖 / 不合格报损
        │
        ↓
  【02 采购退出】──→ 出库冲减库存

                    ┌───────────────── 生产线（转）─────────────────┐
                    │                                               │
  【03 生产】中间品炮制（投料=原药材）──→ 成品包装（投料=中间品）──→ 成品入库

                    ┌───────────────── 销售线（出）─────────────────┐
                    │                                               │
  【07 销售】开票 ──→ 校验（FIFO/账期/信贷）──→ 出库 ──→ 签收
        │                                                        │
        │ 客户退货                                                │ 收款
        ↓                                                        ↓
  【08 销售退回/冲差】──→ 退回验收入库                【09 销售收款】──→ 应收核销

                    ┌───────────────── 支撑（两个支点）─────────────────┐
                    │                                                  │
  【10 WMS 仓储作业】收 / 发 / 存 / 退 的全场景手持与电脑端作业
  【11 商品养护】    在库养护周期 30/90 天、近效期停售、养护不合格报损
```

**串联要点：**

1. **进销两条线对称**：采购 ↔ 销售，采购退出 ↔ 销售退回，采购付款 ↔ 销售收款，四组互为镜像。
2. **质检卡在中间**：01 的检验不合格 → 05 → 02；在库超期 → 06。质检不是独立流程，是**闸门**。
3. **财务在最后收口**：04 / 09 都依赖前面的入库 / 出库单据已审核、处于"待开发票"状态。
4. **WMS 与养护是底座**：10 管物理动作，11 管效期合规，两者贯穿全部流程。

## 六、GMP 与 GSP 的分野

理解这份文档的关键，是先分清两套体系：

| 维度 | **GMP**（药品生产质量管理规范） | **GSP**（药品经营质量管理规范） |
|------|-------------------------------|-------------------------------|
| 适用企业 | **生产型**（药品生产企业） | **经营型**（批发 / 零售 / 流通） |
| 核心环节 | **放行**（QP 质量受权人终判） | **验收**（三态判定） |
| 货物处置 | 放行 → 正常库存可用；不放行 → 先入库再走采购退出 | 合格 → 合格品库；待处理 → 待处理区；不合格 → 不合格品库 + 不合格登记 |
| 退货逻辑 | 有**换包装 / 重新加工**的可能（GMP 第 134、136、137 条） | **不存在换包装改批号**，只能入合格品库重新上架或退上游 |
| 效期 / 停售 | 在库**复验**（超期复检） | **质量复查 + 近效期停售** |
| 仓储硬指标 | 分库存放、温湿度监控、留样（附录·中药饮片 第 24 / 25 / 35 / 36 / 53 条） | 垛间距 ≥5cm、离墙顶 ≥30cm、离地 ≥10cm；相对湿度 **35%–75%**；色标管理（合格绿 / 不合格红 / 待定黄）—— **GSP 第 83 条** |
| FIFO 先进先出 | 销售开票单有 **4 道**自动校验（含 FIFO） | 销售开票单只有 **3 道**（无 FIFO） |

> 文档中凡涉及条款出处的地方都做了标注，可直接引用；如用于正式合规文件，建议再对照最新版规范原文复核。

## 九、关键概念速查

| 术语 | 含义 |
|------|------|
| **放行** | GMP 核心动作，QP（质量受权人）终判物料 / 成品能否使用 |
| **验收（三态）** | GSP 核心动作，判定合格 / 待处理 / 不合格 |
| **先入后退** | 退货类流程的通用原则：货先回库，再冲减原业务 |
| **勾兑** | 将发票与应付 / 应收单据核对匹配（≠ 开票） |
| **FIFO** | 先进先出，GMP 销售开票单强制校验 |
| **批号停售 vs 商品停售** | 前者只停一个批号，后者停整个商品，范围差异大 |
| **一品多价** | 同一商品对不同客户 / 时段的不同价格，需维护优先级 |
| **留样** | 为事后复查留存样品，量 ≥ 全检量，放行后至少留一年 |
| **垛间距 / 色标** | GSP 第 83 条仓储硬指标，现场检查直接对标 |
| **近效期停售** | GSP 经营企业效期管理，临期自动锁定不可销售 |
